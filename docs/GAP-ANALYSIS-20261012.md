## 第二节 · 还缺什么（按严重度排）

### 🔴 A 类 · 商业模式缺口（你赚钱的那部分）

#### A1. 云机 = 骨架全搭好了，就缺「接一个真服务商」和「一个界面」

> ⚠️ **更正**：我第一版报告写「云机没有 API」，**这是错的**。
> 复查发现 API 一直在（走 `/api/desktop/*`），骨架比我说的完整得多。以下为修正版。

| 层 | 状态 | 证据 |
|---|---|---|
| 数据库表 | ✅ **完整** | `016-cloud-desktops.sql`：4 张表（desktops / credentials / provision_jobs / audit_events） |
| 存储层 | ✅ **完整** | `desktop-store.mjs`：创建/状态流转/凭据 AES-256-GCM 加密/限额 5 台/中断任务隔离 |
| **适配器骨架** | ✅ **完整** | `desktop-provider.mjs`：`provision` / `getStatus` / `resetPassword` / `destroy` 四个方法 + **注入式 `transport` 接缝** |
| **服务层** | ✅ **完整** | `desktop-service.mjs`：含能力声明、强证明校验、账号恢复保护 |
| **API 路由** | ✅ **在** | `/api/desktop/*` —— **实测 `GET /api/desktop/capabilities` 返回 200** |
| **真实服务商适配器** | ❌ **没有** | `transport=null` → 所有操作返回 `DESKTOP_UNCONFIGURED` |
| **前端界面** | ❌ **没有** | 「我的 → 云机」实测**跳转到设备页**（`mine.js:135`），不是云机管理 |

**实测证据（我跑的）**：
```
GET /api/desktop/capabilities -> 200
  {"available":false,"provider":"disabled","code":"DESKTOP_UNCONFIGURED",
   "adapterStage":"skeleton","billingEnabled":false,"region":"us-west-2",
   "protocol":"DCV","clientModes":{...}}
GET /api/desktop -> 503 DESKTOP_UNCONFIGURED
```

**➡️ 准确结论**：云机**约 60% 完成**——管道全通，**只差最后两段**：
1. 写一个真实 `transport`（接 AWS WorkSpaces 或 Vultr 或自己搭）
2. 建云机前端界面（现在入口是假的，指到设备页）

**➡️ 好消息**：这个设计很干净——`transport` 是**注入式**的，接新服务商不用改上层。工作量比想象的小。

**➡️ 你提过的「用户赚钱后开始收费」这套，一行代码都没有。**

## 第三节 · ⚠️ 有一个矛盾，需要你先拍板

**你说过两句话，它们互相打架：**

| 你的原话 | 另一句原话 |
|---|---|
| 「**平台无任何收费项目**」 | 「商业模式：**云机转售赚差价**（代办 + 加价服务）」 |

**具体冲突点**：
- 云机的数据库表里有 `price_cents`（售价）、`cost_cents`（成本）两个字段
- **「转售赚差价」本质上就是收费** —— 只是收的是云机差价，不是平台服务费
- 但「平台零收费」是**最强的 Apple 合规防线**（3.1.1 管的是绕过内购）

**三种可能的解法，你选一个**：

| 方案 | 含义 | 合规影响 |
|---|---|---|
| **甲** | 云机差价**不算平台收费**（是硬件转售价），平台服务本身免费 | ⚠️ 需要在商店描述里说清「云机是第三方商品」 |
| **乙** | **真的零收费**，云机也只做「链接」（引导你去 Vultr 自己买） | ✅ 最安全，但**你赚不到差价** |
| **丙** | 云机走**独立实体/独立 App**，与 YBZ 分开 | ⚠️ 复杂，但最干净 |

**➡️ 这个不定，云机就没法往下做。**
