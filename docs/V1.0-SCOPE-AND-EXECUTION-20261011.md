## 一、1.0 到底是个什么产品

### 1.1 用一句话讲清楚（这句话要能用在对朋友、对审核员、对媒体）

> **你告诉它要做什么，它在后台帮你做完，你回来看结果。**

再展开成一句用户能听懂的话：

> **不用盯着它。你描述要干的活，它自己去跑，跑完了通知你。**
> **而且你可以把跑出来的结果，直接分享给你的朋友看。**

### 1.2 1.0 的产品结构（五 Tab，沿用现有结构）

| Tab | 1.0 做什么 | 优先级 |
|---|---|---|
| **工作台** | 描述任务 → 后台执行 → 回来看结果 → 分享结果 | **P0** |
| **消息** | 和 AI 单聊（信息栏）+ 和朋友的群聊 | **P0**（AI 单聊）/ **P1**（群聊） |
| **钱包** | 存多种加密货币（自托管），设置支付密码 | **P2** |
| **发现** | 看别人分享的工作流结果（浏览，不做交易） | P1 |
| **我的** | 头像 / ID / 邮箱绑定 / 密码 / 支付密码 | **P0** |

### 1.3 为什么优先级是「工作台 > 社交 > 钱包」

这是本轮最重要的一次调整，必须说清楚理由：

| 原以为 | 实际 |
|---|---|
| 钱包最重要（区块链产品嘛） | ❌ **没有人会专门为了"存币"来装一个 App**。存币需求早就被主流钱包吃掉了 |
| 社交次之 | ⚠️ 群聊是入口，但**空群聊没人来**——得有东西可聊 |
| 工作台是包装 | ✅ **这才是唯一的"非用不可"**：它是别的 App 干不了的事 |

**逻辑链**：工作台让人**有理由来** → 结果可以分享，所以**有理由叫朋友来** → 朋友来了要付积分，所以**有理由放钱包**。

**倒过来做（先钱包）就会死**：钱包是"配套设施"，不是"进门理由"。

> **注**：Google Play 2026 政策已确认**非托管钱包豁免牌照**（token-browser 原文 "Non-custodial wallets remain exempt"）。
> 所以钱包放 P2 **不是因为合规压力，纯粹是产品逻辑**。这是一个好消息。

## 二、三条主线的 1.0 具体范围

### 2.1 P0｜工作台 + 远程执行（1.0 的命）

**用户视角的完整流程**（这就是验收标准）：

1. 打开工作台 → 用自然语言描述一件事（例：「把这份越南语商品描述翻成英文，再润色成适合亚马逊的标题」）
2. 选执行位置：**本地设备** 或 **云机**（1.0 里云机只对你自己可见）
3. 点开始 → **可以退出去干别的**（这是关键体验：不用盯着）
4. 回来看到结果 → 结果可以一键分享到「发现」
5. 每一步扣积分（现有实现：每步 10 分，`local-points-v1`）

**1.0 要达到的状态**：

| 项 | 现状 | 1.0 目标 |
|---|---|---|
| planner | `local-rules`（本地规则） | **接真实模型**（DeepSeek） |
| executor | `local-file-parser` | 保持（文件工具），云端执行走云机 |
| 模型 | `qwen3:0.6b`（6 亿参数，太小） | **`deepseek-v4-flash`** |
| 异步执行 | 状态机已有，能跑 | 保持，重点验收「退出后台还能跑完」 |
| 分享结果 | ❌ 无 | **新增：把结果发到「发现」** |

**⚠️ 宣传红线（必须守）**：
现在的 `capabilities` 接口自己诚实地写着：
> `'本地规则式计划与文件工具；未连接语言模型、云桌面或真实支付。'`

接上 DeepSeek 之后才能改这句。**在接通之前，对外绝不能宣传"通用 AI 自动干活"**——那会构成虚假宣传。

### 2.2 P1｜社交（群聊 + AI 单聊）

| 功能 | 1.0 | 说明 |
|---|---|---|
| **信息栏和 AI 单聊** | ✅ 必做 | 这是"和 AI 对话"的入口，P0 级 |
| **建群 + 群聊** | ✅ 做，但做浅 | 能建群、能发消息、能拉人。**不做**群机器人、不做群内 AI 协作 |
| **朋友圈 / 结果分享** | ✅ 必做 | 「发现」Tab 里展示别人分享的工作流结果 |
| 头像 / ID 自定义 | ✅ 必做 | 基础账号能力 |
| 邮箱绑定 | ✅ 必做 | 依赖「接真实邮件」这项前置 |
| 密码 / 支付密码 | ✅ 必做 | 支付密码是钱包解锁用的，与登录密码分离（现有设计已分离） |

**为什么群聊"做浅"**：
市场调查显示，2026 年 1 月百度文心、腾讯元宝、阿里同一时间上线了 AI 群聊，
OpenAI 2025 年 11 月上线 ChatGPT 群聊（上限 20 人），Snap 花 4 亿美元买 Perplexity。
**这是大厂正在用钱砸的赛道，1.0 不要正面对撞。**
你的差异化在「群聊里有别人真正跑出来的工作流结果可看」，而不是"更聪明的群机器人"。

### 2.3 P2｜钱包（存着，但不做主推）

| 功能 | 1.0 | 说明 |
|---|---|---|
| 多币种存储 | ✅ 具备 | 现有实现只开 **BSC 测试网（chainId 97）** |
| 支付密码 | ✅ 必做 | 5 分钟自动锁定 + 2 分钟预览窗口（现有） |
| 助记词 / 私钥 | ✅ 用户自持 | 现有设计：密钥与账号密码分离，keystore 三重校验 |
| **主网** | ❌ 不做 | 代码里**没有主网开关**（注释明写 "There is no mainnet toggle."） |
| **法币入金 / 提现** | ❌ 不做 | 需要持牌机构，1.0 不碰 |
| **积分兑币** | ❌ 不做 | 代码级 403 硬拦（`POINTS_NONTRANSFERABLE`） |

> **1.0 钱包的正确说法**：**「你的币，钥匙在你自己手里。我们碰不到。」**
> 不要说"支持多链资产管理"，那是 2.0 的话。

## 三、技术清单（这一节给 Codex 看）

### 3.1 【关键】接 DeepSeek 需要改代码，不是填 Key

这是上一轮审计发现的、**最容易被低估的一处**。

**现状**（`yubenzhe-deploy/server/ai-provider.mjs` 第 7-8 行）：

```js
const ENDPOINT = 'https://api.openai.com/v1';
const ALLOWED_HOSTS = new Set(['api.openai.com']);
```

**含义**：host 白名单是**硬编码**的。只填 `AI_API_KEY` 不管用——
请求会被自己的白名单挡在门外。

**要改的**：

```js
const ENDPOINT = 'https://api.deepseek.com/v1';
const ALLOWED_HOSTS = new Set(['api.deepseek.com']);
```

**要配的**（`start.mjs` 已支持的环境变量）：

| 变量 | 值 |
|---|---|
| `AI_PROVIDER` | `openai`（DeepSeek 是 OpenAI 兼容接口，沿用该分支） |
| `AI_MODEL` | `deepseek-v4-flash` |
| `AI_API_KEY` 或 `AI_API_KEY_FILE` | 你的 DeepSeek Key |

**DeepSeek 事实卡**（已核实）：
- `base_url` = `https://api.deepseek.com`（`/v1` 后缀是可选的，与模型版本无关）
- 模型名：`deepseek-v4-flash`（便宜档）/ `deepseek-v4-pro`（强档）
- ⚠️ 旧 ID `deepseek-chat` / `deepseek-reasoner` **已于 2026-07-24 退役**，别填错
- 完全 OpenAI 兼容，走 `/chat/completions`
- 价格：**输入 ¥0.10 / 输出 ¥9（每百万 token）**——是目前主流里最便宜的一档
- 免费层约 10 请求/分钟

**同时要复核的**：现有 `AI_LIMITS` 限流是按 OpenAI 的成本设计的，
换成 DeepSeek 后成本大降，可以**适当放宽** `dailyTasks` / `maxOutputTokens`。
（建议：先别动，跑一周看真实用量再调。）

### 3.2 接真实邮件（P0，一个下午的事）

**现状**：`server/account-mail.mjs` 全文 14 行，只有三个适配器：
`createDisabledMailAdapter`（默认，直接抛错）/ `createSimulationMailAdapter`（仅 loopback）/ `createInternalPreviewMailAdapter`（仅内测域）。

**要实现的接口**（已确认签名）：

```js
{ mode: 'provider', async send({ to, kind, code, expiresAt, locale }) { ... } }
```

**要做的**：
1. 选服务商（SendGrid / 阿里云邮件推送 / AWS SES 皆可）
2. 实现上面的 `send`
3. 配发信域名的 **SPF / DKIM / DMARC**（不配会被判垃圾邮件）
4. 注入 `EMAIL_OTP_SECRET`（**≥32 字符**，代码强制校验）
5. 加并发/频率限制 + 退信处理

### 3.3 重建 MANIFEST 基线（P0，10 分钟）

**问题**：`MANIFEST.json` 写的版本是 `0.9.0`，实际代码是 `0.14.0-dev.7`。
实跑比对 **127 项文件不一致**，不加 `--allow-changes` 时**直接判 failed**。

**含义**：这道防篡改保险**实际已经失效**——它本来是用来验"文件有没有被偷换、有没有混进私密文件"的。

**要做的**：用当前 dev.7 源码重新生成基线，旧基线留档对照。

### 3.4 其余技术项（按优先级）

| 优先级 | 事项 | 说明 |
|---|---|---|
| P1 | Windows 代码签名证书 | 否则用户看到「未知发布者」，严重影响信任 |
| P1 | Android 实体机验收 | 现在只在**模拟器**上验过 |
| P1 | 区块浏览器源码验证 | 成本低、收益高，**建议插队做** |
| P2 | i18n 接通 | 见 3.5——它比文档说的还严重 |
| P2 | 死代码归档 | `scripts/simulate-group-gifts-100.mjs` 移到 `archive/` |

### 3.5 i18n 是彻底悬空的（比文档描述更严重）

审计文档写的是「未进入 app.js 运行导入链」。
我实际 grep 了整个 `tongban/src/`：**`import ... from './i18n'` 命中数为 0**。

也就是说 `i18n.js`（54 行）**没有任何模块引用它**——不是"接了没启用"，是**根本没接线**。

**对全球市场来说中英双语是刚需**，好在模块已有，缺的是接入。工作量不大。

**你的选择是个人账号，所以要立刻开始招人。**

**你的实现正好符合**：密钥在用户设备、无托管、无代付。
**如实填就行，不要含糊，也不要过度解释。**

## 五、1.0 明确「不做」的清单

这一节和「做什么」一样重要。**每接一个东西进来，就多一份运营、客服、法律的责任。**

| 不做 | 为什么 |
|---|---|
| ❌ 支付 / 收款 | 商业模式未验证前不接。⚠️ **定价前必须拿律师意见**（涉及"工具"滑向"预付卡"的风险） |
| ❌ 云机对外开放 | 1.0 只开 1 个账号给自己跑通，**不对用户开放** |
| ❌ 节点租赁 | 3 年起，现在做 = 把"以后的事"变成"今天的债务" |
| ❌ 链上发币 / 红包 / 空投 | 高危业务，已退役的旧资产接口保持 410 |
| ❌ 赏金论坛 / 服务商入驻 / 作者分佣 | 四边市场 0×0×0×0，必须先有一边转起来 |
| ❌ 活跃榜 | 运营负债，无用户基数时是空的 |
| ❌ 主网与真实收费 | 合约**未审计**（`package.json` 自己标了 `"unaudited"`），一旦开主网审计是不可绕过的第一道门 |
| ❌ 积分兑资产 / Gas 代付 | 代码级已锁死，保持 |
| ❌ iOS | 现在停在 0.13.0，越狱 ad-hoc 签名，落后整整一个版本 |
| ❌ AI 群聊机器人 | 不要和大厂正面对撞 |

## 七、2.0 / 3.0 的解锁条件

**不要提前做 2.0 的事，除非下面这一条成立：**

> **有 3 个以上的人，在没人催的情况下，自己回来用了第二次。**

这一条成立 → 说明「工作台」是真的有人要 → 才谈得上后面的。

| 版本 | 解锁条件 | 内容 |
|---|---|---|
| **1.0** | 现在 | 工作台 + 社交 + 钱包（测试网），Android + Windows |
| **2.0** | 1.0 有人重复使用 | 支付接入 + 云机对外开放 + 工作流可以被别人一键搭起来 |
| **3.0** | 2.0 有人付费 | 节点租赁 + 分佣体系 + 主网（含合约审计） |

**为什么这么定**：
1.0 想验证的是「**有没有人真的需要这个工具**」。
这个问题**不需要**支付、不需要云机对外、不需要发币——所以 1.0 不做这些，是对的。
