## 二、最重要的优化：核心叙事有一条断链

### 2.1 断在哪

1.0 核心叙事是四步：

```
① 你告诉 AI 要什么    → ✅ 任务计划（做了）
② 它在后台干完        → ⚠️ 只有「本地规则 + 文件处理」，没有通用 AI 模型
③ 你回来看结果        → ✅ 任务成果（做了）
④ （隐含）分享结果     → ❌ 完全没有
```

**问题②**：工作台 capabilities 自述原文：
> `'本地规则式计划与文件工具；未连接语言模型、云桌面或真实支付。'`

**问题④**：`docs/V1.0-SCOPE` 第 42 行明确把「**分享结果**」写进了工作台定义：
> `| 工作台 | 描述任务 → 后台执行 → 回来看结果 → 分享结果 | P0 |`

但它在你的 dev.8 清单里**根本不存在**。

### 2.2 这意味着什么

> **1.0 的核心叙事现在只走了 3/4 步。**
> 用户能「回来看到结果」，但**结果出不去** —— 出不去就不会有人问「你这是什么 App」，也就没有传播。

**这是 1.0 最该补的一个洞，而且它比「接云电脑」重要得多。**

### 2.3 修正建议：1.0 的「优化方案」

```
第 1 优先（补断链）：
  ① 接一个真实模型（DeepSeek，只差配 Key）
     → 让「它在后台干完」变成真的 AI，不是规则解析文件
  ② 做「结果分享到发现」
     → 补上第 4 步，让核心叙事闭环

第 2 优先（收口）：
  ③ 把「赏金/服务商」从工作台首页撤下（代码留着）
  ④ 把「云电脑」入口明确标注为「内测中，暂不开放」
     → 现在是空状态页，但和首页其它功能平级展示，会误导

第 3 优先（降噪）：
  ⑤ i18n 死代码要么接通、要么归档（3KB 文件，全前端 0 引用）
```

## 三、⚠️ 一个必须指出的矛盾：云电脑 vs 1.0 核心

你上一轮让我做的**云电脑规划**，和 1.0 核心**是冲突的**：

| | 1.0 说的 | 我们上一轮做的 |
|---|---|---|
| 云电脑 | 「**不对用户开放**，只开 1 个账号给自己跑通」 | 建了完整后端骨架 + 规划了对外卖钱 |
| 矛盾程度 | — | **轻度冲突** |

**怎么理解这个矛盾**（我的判断）：

1. **不白做**。骨架建好了，2.0 直接能用，现在停手不浪费。
2. **但 1.0 阶段，云电脑的定位应该是「自用工具」，不是「商品」**。
   - 建 1 个账号，**你自己用**，把它当成「验证远程执行到底有没有用」的实验
   - **不要**在 App 里给用户看购买入口
3. **你最新的消息说「远程是客户主要来源吸引点」** —— 这可能是对的，但它属于 **2.0 的赌注**，
   而 2.0 的解锁条件是「3 个人自己回来用第二次」。
   **顺序不能倒**：先有第二次，再谈云电脑卖钱。

> **一句话**：云电脑**保留、冻结、自用验证**；1.0 不宣传、不开放购买。
