第二部分：新增「云电脑」数据模型与服务商适配层（只写代码，不接真实服务商）
-----------------------------------------------------------

背景：我们要做"客户在 App 里一键开通一台云端电脑"的功能。
本次只做数据模型 + 适配层骨架 + 单元测试，**不要真的调用任何云服务商 API**。

2.1 新建数据库表（放在 yubenzhe-deploy 现有的 SQLite 迁移体系里，
    遵循项目现有的建表风格和命名习惯）

    表 1：cloud_desktops
      字段：
        id TEXT PRIMARY KEY
        user_id TEXT NOT NULL          -- 归属用户，外键指向现有用户表
        provider TEXT NOT NULL         -- 'aws-workspaces' | 'other'
        provider_desktop_id TEXT       -- 服务商侧 ID，异步回填
        plan TEXT NOT NULL             -- 'basic' | 'standard' | 'power' | 'graphics'
        region TEXT NOT NULL           -- 'us-west-2' 等
        protocol TEXT                  -- 'DCV' | 'PCoIP'，默认 'DCV'
        state TEXT NOT NULL            -- 'creating'|'available'|'stopped'|'error'|'terminated'
        created_at INTEGER NOT NULL
        available_at INTEGER
        terminated_at INTEGER
        cost_cents INTEGER             -- 我们支付的成本（分）
        price_cents INTEGER            -- 我们向用户收的（分）
        auto_stop_minutes INTEGER      -- 空闲自动关机，默认 60
      索引：user_id、state

    表 2：cloud_desktop_credentials
      字段：
        desktop_id TEXT PRIMARY KEY    -- 外键指向 cloud_desktops
        registration_code TEXT         -- 注册码（AWS 用）
        username TEXT NOT NULL
        password_ciphertext BLOB NOT NULL
        password_iv BLOB NOT NULL
        password_tag BLOB NOT NULL
        realm TEXT
        created_at INTEGER NOT NULL
        updated_at INTEGER NOT NULL

      加密要求（重要）：
        - 使用 AES-256-GCM
        - 密钥来自环境变量 DESKTOP_CRED_KEY（32 字节）
        - 如果 DESKTOP_CRED_KEY 未配置，**写入时必须抛错**，不允许明文落库
        - 提供 decryptPassword(desktopId) 函数，供"用户点击查看密码"时调用

    表 3：desktop_provision_jobs
      字段：
        id TEXT PRIMARY KEY
        desktop_id TEXT NOT NULL
        request_id TEXT NOT NULL UNIQUE   -- 幂等键
        payload_hash TEXT NOT NULL        -- 请求内容哈希
        status TEXT NOT NULL              -- 'queued'|'running'|'succeeded'|'failed'
        attempts INTEGER NOT NULL DEFAULT 0
        last_error TEXT
        created_at INTEGER NOT NULL
        updated_at INTEGER NOT NULL

2.2 新建 yubenzhe-deploy/server/desktop-provider.mjs

    导出以下函数（本次全部为骨架实现，不调真实 API）：

      createDesktopProvider(config) → 返回 provider 对象
        如果 config 中没有凭据 → 返回 disabled provider
        所有方法调用时返回 { ok:false, code:'DESKTOP_UNCONFIGURED', message:'尚未配置真实云电脑服务商' }
        （参考 workbench-service.mjs 里 DESKTOP_UNCONFIGURED 的现有处理方式，
          也参考 ai-provider.mjs 的 createDisabledXXX 模式，保持风格一致）

      provider.provision({ userId, plan, region, requestId }) → { jobId }
        - 幂等：同 requestId 且 payload 一致 → 返回已有 jobId
        - 同 requestId 但 payload 不同 → 返回 409 错误
        - 参考 points-service.mjs 里已有的 requestId 幂等实现，保持一致

      provider.getStatus(desktopId) → { state, raw }

      provider.resetPassword(desktopId, newPassword) → { ok }
        必须实现 —— 因为用户必须能自己改密码，不能只能找我们

      provider.destroy(desktopId) → { ok }
        必须实现 —— 用户必须能一键彻底注销云电脑

    环境变量（全部可选，未配置时 disabled）：
      DESKTOP_PROVIDER        'disabled' | 'aws-workspaces'
      DESKTOP_REGION          默认 'us-west-2'
      DESKTOP_CREDENTIALS_FILE  优先读文件（避免密钥进日志/进程列表）
      DESKTOP_CRED_KEY        凭据加密密钥

    绝对不要在代码里写死任何 AccessKey / SecretKey。

2.3 提供 HTTP 接口（挂在现有后端路由体系里，遵循现有路由注册方式）

    POST /api/desktop/provision
      body: { plan, region?, requestId }
      → 202 { jobId, desktopId }
      → 503 DESKTOP_UNCONFIGURED（未配置时）

    GET  /api/desktop/:desktopId
      → 200 { state, plan, region, createdAt, availableAt, cost, price }
      → 403 如果不是当前用户的机器（权限必须校验，不能越权看别人的）

    GET  /api/desktop/:desktopId/credentials
      → 200 { registrationCode, username, password, realm, clientDownloadUrls }
      → 403 非本人
      说明：clientDownloadUrls 要返回服务商官方客户端的下载地址
            （Windows / macOS / iOS / Android / Web），
            目的是让用户能脱离我们的 App 使用

    POST /api/desktop/:desktopId/reset-password
      → 200 { ok:true }

    POST /api/desktop/:desktopId/terminate
      → 200 { ok:true }

    重要：以上所有接口在未配置服务商时，必须返回 503 + DESKTOP_UNCONFIGURED，
    而不是 500 或崩溃。这是"功能存在但未接通"的标准状态。
    同时 capabilities / 健康检查接口里要新增 desktop 字段描述这个状态。

2.4 单元测试（新增 tests/desktop-provider.test.mjs）

    必须覆盖：
    - 未配置凭据时 provision 返回 DESKTOP_UNCONFIGURED
    - 幂等：同 requestId + 同 payload 返回同一个 jobId
    - 幂等冲突：同 requestId + 不同 payload 返回 409
    - 凭据写入：DESKTOP_CRED_KEY 缺失时必须抛错
