第二部分：新增「自用档位」启动脚本
-----------------------------------------------------------

背景：现有 `scripts/start-m0.mjs` 是**隔离测试档**，它主动删掉一切真实服务配置：
```js
delete process.env.AI_API_KEY;
delete process.env.AI_API_KEY_FILE;
process.env.AI_PROVIDER='disabled';   // ← 第 21 行，就是这里锁死了 AI
```
这是**正确的**（M0 就该隔离）。但作者需要一个**真实的个人使用档位**。

请新建 `yubenzhe-deploy/scripts/start-personal.mjs`，要求：

1. **命名与结构**：参照 `start-m0.mjs` 的写法，保持风格一致（同样的 resolve 方式、
   同样的 settings 写法、同样的注释密度）。不要另起一套风格。

2. **与 M0 的关键区别**（这是本脚本存在的意义）：

   | 项 | start-m0.mjs（测试档） | start-personal.mjs（自用档） |
   |---|---|---|
   | `M0_SIMULATION` | `'true'` | **`'false'`** |
   | `AI_PROVIDER` | 强制 `'disabled'` | **从环境变量读，默认 `'openai'`** |
   | `AI_API_KEY` / `AI_API_KEY_FILE` | 主动 delete | **保留，从环境变量读** |
   | 邮件 | 模拟 | 优先读真实配置，未配置则回退模拟 |
   | `INTERNAL_PREVIEW` | 无 | **`'true'`**（因为真实邮件适配器要求它） |
   | 数据目录 | `yubenzhe-m0-state` | **`yubenzhe-personal-state`**（独立，不污染测试数据） |

3. **端口**：默认 `M0_PORT`（18914）已占用，自用档默认端口用 **`PERSONAL_PORT`，默认 `18930`**。
   同样校验 `1024–65535`。

4. **必须打印启动摘要**（这个很重要，方便作者确认档位对了）：
   ```
   === 自用档位已启动 ===
   地址：       http://localhost:18930
   数据目录：   <绝对路径>
   AI 供应商：  openai / deepseek-v4-flash  (或：未配置，AI 功能不可用)
   邮件：       真实投递 / 模拟
   钱包网络：   BSC 测试网 (chainId 97)
   云电脑：     未配置（不开放）
   =======================
   ```
   - ⚠️ **不要打印 API Key 本身**，只打印「已配置 / 未配置」

5. **启动前检查**（缺配置时给出清楚的提示，不要直接崩）：
   - 如果 `AI_PROVIDER` 已配置但 `AI_API_KEY` 和 `AI_API_KEY_FILE` 都没有
     → 打印警告「AI 已启用但缺少密钥，AI 功能将不可用」，**继续启动**（不要 throw）
   - 如果 `INTERNAL_PREVIEW=true` 但 `EMAIL_OTP_SECRET` 少于 32 字符
     → 参照 `start.mjs` 第 23 行的做法（那里是 throw）。这里也 throw，
       但错误信息要说明「请设置至少 32 位随机字符的 EMAIL_OTP_SECRET」
   - 如果设置了 `EMAIL_OTP_SECRET` 但没有 `EMAIL_PROVIDER`
     → 打印「邮件将使用模拟码」，**继续启动**

6. **绝对不要**在这个脚本里硬编码任何密钥。所有密钥从环境变量或密钥文件读。

7. 在 `yubenzhe-deploy/README.txt`（或项目现有的说明文件）里加一段
   「自用档位怎么启动」，包括需要设置哪些环境变量、怎么拿 DeepSeek Key。
