步骤 2/3：接入真实邮件投递服务商
================================

问题：server/account-mail.mjs 只有三个适配器，没有一个能真的发信：
  createDisabledMailAdapter        → mode 'disabled'，默认，send() 直接抛错
  createSimulationMailAdapter      → mode 'simulation'，只塞内存 outbox，仅限 loopback
  createInternalPreviewMailAdapter → mode 'simulation'，仅限 HTTPS 内测域

文件末尾注释已写明契约，按它实现：
  // A delivery provider implements {mode:'provider',send({to,kind,code,expiresAt,locale})}.

新增一个 createHttpMailAdapter，返回 { mode:'provider', async send({to,kind,code,expiresAt,locale}) }。
原有三个适配器一行不动。

调用方的硬约束（必须先读再配合）：
  server/account-access.mjs 第 13 行：
    if(mail.mode==='provider'&&(!config.otpSecret||config.otpSecret.length<32)) throw Error(...)
  即 mode 为 provider 时 EMAIL_OTP_SECRET 必须存在且 ≥32 字符，否则服务启动直接失败。

  server/account-access.mjs 第 24 行 ensureMail()：
    disabled → fail 503 / simulation 非 loopback → 403。
  确认新增的 provider 模式不被这两个分支拦到。

接线点：
  server/product-modules.mjs 第 15 行现在是
    const mail=mailAdapter||(internalPreview?...:simulation?...:undefined);
  在这里增加 provider 分支：环境变量配好时返回 createHttpMailAdapter(...)，
  没配就维持原行为（undefined，上层落到 disabled）。
  server/start.mjs 的环境变量校验也要加新变量名（先读再改，不要猜）。

配置全部从环境变量读，不要硬编码任何 Key 或发信地址。
**优先支持 EMAIL_API_KEY_FILE（读文件）而不是直接放环境变量** —— Key 进环境变量容易进日志。
参考 ai-provider.mjs 的既有写法，它读文件时会检查 statSync().mode & 0o077。

安全要求（对齐 ai-provider.mjs 的既有标准）：
  - endpoint 必须 https，否则构造失败
  - fetch 用 redirect:'error'
  - 出错时不要把上游响应体拼进错误消息（上游可能回显你的 Key）
  - AbortController 超时，10 秒量级上限
  - 日志里不得出现验证码明文，只记 challengeId / 邮箱域
  - to 地址做格式校验，复用 normalizeEmail 的思路（注意别造成循环依赖）

邮件正文用现有语言策略，第一版中英各一份即可，不要发明第三语言。
正文至少含：验证码、有效期 expiresAt、「不是本人操作请忽略」提示。
绝不索要助记词、私钥、密码。

.env.example 追加（默认保持关闭）：
  # Real email delivery (optional). When unset, email verification stays disabled.
  # EMAIL_PROVIDER=http
  # EMAIL_ENDPOINT=https://api.example-mail.com/v3/mail/send
  # EMAIL_API_KEY_FILE=/run/secrets/email_api_key
  # EMAIL_FROM=no-reply@yourdomain.com
  # EMAIL_OTP_SECRET=<at least 32 random characters; persistent>

新增测试至少覆盖：
  1) mode 是 'provider'
  2) 注入 mock fetchImpl，断言请求打到配置的 endpoint 且带 Authorization
  3) endpoint 是 http: 时构造失败
  4) 上游返回 500 时 send() 抛错，且错误消息里不含上游响应体内容
  5) disabled / simulation / internal-preview 三个适配器行为不变（回归）

明确不要做：
  - 不要改原有三个适配器的行为
  - **不要默认打开邮件**，默认必须仍是 disabled，避免误发信
  - 不要提交真实 API Key 或真实发信域名
  - 不要自行注册或购买任何邮件服务（那是人的运营动作）
  - 不要引入重量级 SDK，优先原生 fetch
