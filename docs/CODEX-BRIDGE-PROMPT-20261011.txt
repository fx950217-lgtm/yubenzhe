新增三个文件（放在 tools/local-bridge/，独立目录，不污染主项目）
================================

【1】tools/local-bridge/bridge.mjs

启动参数：
  --port  默认 18930
  --cwd   允许执行的目录（必填，不给就报错退出）

启动时生成 6 位随机数字配对码，在终端打印成这样：

  ==================================================
    愚笨者 · 本地桥已启动
  --------------------------------------------------
    配对码： 4 8 2 9 1 3
    局域网地址：http://192.168.1.11:18930
    允许执行目录：C:/Users/.../yubenzhe
    提示：手机连同一个 WiFi，打开上面的地址
  ==================================================

端点：
  GET  /health         → {ok:true, device, codex:"0.153.4"}
  POST /pair/verify    → body {code}，码对返回 {token}，错返回 401
  POST /task           → 需 Authorization: Bearer <token>，SSE 流式返回

SSE 事件格式：
  {"type":"start","taskId":"..."}
  {"type":"chunk","text":"..."}
  {"type":"done","exitCode":0,"durationMs":12345}
  {"type":"error","message":"..."}

必须实现的安全约束（一个都不能少）：
  * 配对码每次启动随机生成
  * POST /task 必须带正确 token，否则 401
  * 可执行目录只能来自 --cwd 启动参数，请求体不能覆盖
  * prompt 长度上限 4000 字符
  * 单次执行超时 5 分钟，超时要 kill 子进程
  * 并发上限 1（同时只能跑一个任务，第二个请求返回 429）
  * 日志只记 taskId 和 prompt 长度，**不记录 prompt 全文**

限制：不要引入任何 npm 依赖，只用 node 内置模块。


【2】tools/local-bridge/mobile.html

单文件，原生 HTML + JS，不引入任何框架（与项目现有风格一致）。

  - 打开先让用户输配对码，成功后 token 存 localStorage
  - 一个输入框 + 发送按钮 + 消息列表（用户消息和 AI 回复要视觉区分）
  - AI 回复必须流式显示（fetch + ReadableStream 读 SSE，一边来一边显示）
  - 顶部状态栏显示：● 已连接 我的电脑 / ○ 未连接
  - 移动端适配（手机上要能正常用，字体不能太小，输入框不能被键盘挡住）
  - 显示任务耗时
