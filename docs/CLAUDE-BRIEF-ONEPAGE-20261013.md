## 一、这个产品是什么（一句话）

**你对着你的电脑说一句人话，它替你干活；干到需要你拿主意的地方，它停下来问你；你点一下，它接着干。**

人做决策，机器干活。手机是遥控器，电脑（自己的或云端买的）是干活的机器。

## 二、这个产品的角色分工（先看懂这个比喻，后面所有决策都靠它）

用户用了一个**极准的比喻**，你要先接受这个心智模型，因为它决定了架构：

| 角色 | 现实对应 | 干什么 |
|---|---|---|
| 👑 **皇帝** | **用户本人** | 拍板、定方向、批红 |
| 🏛️ **太监** | **愚笨者 / YBZ（我们的产品）** | 把皇帝的话送到该去的地方，把结果带回来；**遇到要拍板的地方停下来问皇帝** |
| 🧠 **宰相** | Codex / Claude Code / Qwen Code / OpenCode / Kimi Code CLI | 接到命令**动手执行**（改文件、跑命令、装软件） |
| 🎓 **参谋 / 谋士** | **模型**（GPT / Claude / DeepSeek / GLM / Qwen / Kimi） | **只出主意，不动手** |
| 🤝 **外交** | 微信 / 社交 | 对外联络、拉人（暂不接） |
| 🍚 **后勤** | 购物 / 支付 / 物流 | 物资钱粮（暂不接） |

### 关键一句：**宰相 ≠ 参谋**

**宰相（Claude Code 等）是个"空壳子"，它自己没有脑子。** 它身上有个插槽，**参谋（模型）插进去它才能干活**：

```
Claude Code（宰相/壳）  +  Claude 模型（参谋/脑）  =  能干活
Codex        （宰相/壳）  +  GPT 模型（参谋/脑）     =  能干活
Qwen Code    （宰相/壳）  +  Qwen 或 Ollama（参谋） =  能干活
```

**这个区分极其重要**：
- **封号封的是参谋**（Claude 模型的账号）
- **宰相还在位**（Claude Code 这个壳照跑不停）
- **换个参谋**（把 `ANTHROPIC_BASE_URL` 指向别家模型），**宰相继续上朝**

**所以架构上不要把"宰相"和"参谋"焊死在一起。**

### 宰相名录（谁能真干活）

| 宰相 | 出身 | 开源？ | 能干活？ | 备注 |
|---|---|---|---|---|
| **Codex** | OpenAI | ❌ | ✅ 强 | 现在唯一在用的 |
| **Claude Code** | Anthropic | ❌（All rights reserved） | ✅ 强 | 壳闭源，但支持 `ANTHROPIC_BASE_URL` 换参谋 |
| **Qwen Code** | 阿里通义 | ✅ **Apache-2.0** | ✅ | **真开源，可打包进安装包**；`qwen -p` 无头模式；可接 Ollama |
| **OpenCode** | 社区 | ✅ MIT | ✅ | 第三方横评最快 + 最省 token |
| **Kimi Code CLI** | 月之暗面 | ✅ MIT | ✅ | 256K 上下文；正在 Python→Node 重写 |
| **CodeBuddy Code** | 腾讯 | ❌（但免费） | ✅ | 有 `-p` 无头模式 |
| **WorkBuddy** | 腾讯 | ❌ | ✅ | 桌面应用，无 CLI 入口，不好派活 |

**⚠️ 坑**：**DeepSeek、GLM、Moonshot 是"参谋"不是"宰相"** —— 它们只有模型，没有官方编码 CLI。别去它们官网找"壳"。

### 我们这个"太监"的天职：**同时伺候多个宰相**

**皇帝不会只用一个宰相。** 有的宰相擅长文（写代码），有的擅长武（跑命令），有的参谋便宜（Ollama 免费）。

**产品最终形态**：

```
皇帝（用户）说一句人话
   ↓
太监（愚笨者）判断：这事该派给谁？
   ↓
   ├─ 需要写代码   → Codex
   ├─ 需要通用任务 → Claude Code
   ├─ 需要省钱/离线 → Qwen Code + Ollama
   └─ 后续再加
   ↓
宰相（壳）+ 参谋（模型）一起干
   ↓
太监把结果带回来；遇到要拍板的地方 → 停下来问皇帝（决策卡）
```

**注意**：中间那个"判断派给谁"的逻辑**现在还没有** —— 现在的逻辑是"默认派给 Codex"。这就是第六批要做的事。

## 五、我要你做的事（按这个顺序，做完一件做下一件）

### 第一批 · 让「干活够得着业务文件」（最重要）

**问题**：现在电脑端 Codex 的干活目录是**自动分配**的（`yubenzhe-desktop/src/device-manager.cjs:18`），向导里**只显示不给改**（`device-wizard.html` 里只有 `<p id="workspace">`）。这导致用户派活时，Codex **看不到自己的业务文件**（比如 `D:\房产\客户表.xlsx`）。

**要做**：
1. 向导里增加「选择工作目录」按钮（文件夹选择器），用户能指定，比如 `D:\房产\`
2. 派活时手机上也要能**看到**这个目录名（让人知道 AI 在哪干活）
3. 安全边界不放松：仍然用 Codex 原有的 `workspace-write` 沙箱，**不许扩大权限**
4. 加测试：指定目录后任务能读到该目录文件

### 第二批 · 「AI 看不到的地方」（用户最在意的心理门槛）

**问题**：用户电脑上有客户合同、身份证照片、`密码.txt`。他不敢用 AI，因为**不知道 AI 会不会读到**。现在这个功能**完全没有**。

**要做**：
1. 电脑端加一个「排除目录」列表，用户能把 `D:\合同\`、`密码.txt` 加进去
2. **必须是技术性隔离**（在连接器层挡住，不是"约定不看"）—— 这是关键，口头承诺没用
3. 手机上能一眼看到「哪些地方被排除了」
4. 加测试：被排除目录里的文件，任务读不到

### 第三批 · 设备舰队（用户是"超级个体"，机器多）

**问题**：用户有好几台机器（本地电脑 + 美国/新加坡/日本/国内的云机 + 平板）。
- **现在最多只能连 5 台**（`yubenzhe-deploy/server/personal-devices.mjs:59` 硬编码 `n>=5` → `DEVICE_LIMIT`）
- **没有"地区"概念**（`022-device-claims-capabilities.sql` 里 `source` 只有 `local/cloud/server`）
- **没有舰队总览页**（看不出哪台在忙、总共几条任务在跑）
- **没有自动选机**（不能说"找台空闲的跑"）

**要做**：
1. 放开上限：5 → 20（改成可配置，别硬编码）
2. 设备加**标签**和**地区**字段（地区：自己填，比如"美国/新加坡/日本/国内"）
3. **舰队总览页**：一台一行/一卡，显示 在线没 / AI 在线没 / 正在跑什么 / 等了几条决策 / 空闲没
4. 派活时能按"空闲 + 地区"筛选，**可选**自动选（默认还是手动选，别擅自改用户习惯）
5. 加迁移（编号从 **029** 开始）+ 测试

**注意**：平板只能当遥控器（看进度、点决策），**不能当干活机器**（装不了 Windows 的 Codex）。这个要在 UI 上说清楚，别让用户误以为平板能跑任务。

### 第四批 · 多任务分别看进度

**问题**：用户一次说三件事（"1. 整理表 2. 写文案 3. 算利润"），现在被当成一件事，**只有一条进度**，看不出"图片做到第几张了"。

**要做**：
1. 一句话里识别出多件事，**每条给独立进度**
2. 全部做完**统一通知一次**，别三条分别震（用户的作息很重要，他明确要求"只在干完/卡住/要拍板才提醒"）

### 第五批 · 通知纪律 + 夜间静默（用户的硬要求）

**问题**：用户明确说过：**"别每一步都烦我"**。他要的是只有三类才通知：**干完了 / 卡住了需要拍板 / 出错了**。

**要做**：
1. 把上面这条**硬编码进产品**，不是配置项
2. **夜间静默 22:30–07:00 默认开**：晚上只记录，不响
3. 加测试：过程中零通知、三类必通知

### 第六批 · 建「宰相池」：让太监能伺候多个宰相（架构性改动）

**问题**：用户在电脑上装了 Codex、Claude、Ollama、WorkBuddy。
现在 `ai-registry.mjs` 里 **Claude 和 WorkBuddy 的 `executionMode` 是 `'disabled'`**，**认得出但派不了活**。Ollama 是 `'chat-only'`（只能聊，不能读文件跑命令）。**真正能干活只有 Codex 一个。**

翻译成朝廷的话：**满朝文武，只有 Codex 一个人上朝。**

**这一步的核心不是"多接一个 AI"，是"证明太监能伺候多个宰相"这个架构成立。**
只接一个的时候那叫"专用工具"，不叫"朝廷"。所以**先把架子搭对，再加人**。

**要做**：

1. **架构改造：把"宰相"抽象成 runner 插件**
   - 现在 `codex-runner.mjs` 是写死的。要改成 **runner 注册表**：`codex-runner` / `claude-runner` / `qwen-runner` 并列，统一接口（接任务 → 执行 → 回报 → 遇决策点停）
   - `ai-registry.mjs` 里的 `executionMode` 变成 runner 是否注册的标志，而不是硬编码字符串
   - **不要动 Codex 的现有行为**，它是唯一跑通的，别搞坏

2. **第二宰相：招 Qwen Code（优先做这个）**
   - 理由：✅ **真开源（Apache-2.0）能合法打包** / ✅ **可接 Ollama = 免费** / ✅ **中文原生** / ✅ **有 `qwen -p` 无头模式**，跟 `codex exec` 一样好派活
   - 安装：`npm install -g @qwen-code/qwen-code@latest`（需 Node 22+）
   - 照着 `codex-runner.mjs` 写一个 `qwen-runner.mjs`
   - **给用户一个"完全免费"的选项** —— 这是产品价值，不是附属品

3. **第三宰相：把 Claude 从 `'disabled'` 打开**
   - Claude Code **不是开源软件**（GitHub 那个 14 万 star 的仓库只是 issue 区 + 文档，`LICENSE.md` 一行 All rights reserved；npm 装下来是编译后二进制，不是源码）
   - **但这不影响集成** —— 因为我们的模式是「**用户自己装在电脑上、自己登录，平台只负责派活**」，不是"把 Claude Code 打进我们的安装包"
   - 所以：照着 `codex-runner.mjs` 补一个 `claude-runner.mjs`，跟 Codex 同一个模式
   - **闭源不是障碍，"自装派活"这个模式完全成立**，这跟 Codex 处境一样（Codex 也是闭源的）

4. **WorkBuddy：暂时搁置**
   - 它是桌面应用，**没有命令行入口**，不好派活。别硬做。留着 `'disabled'`，写注释说明原因

5. **安全要求不放松**（跟 Codex 一致）：
   - 登录由**用户本人在自己电脑上完成**，**平台绝不代登录、绝不代存凭据**
   - 每个 runner 都继承 Codex 的沙箱约束：`workspace-write`、关闭 `browser_use`/`computer_use`/`plugins`/`hooks` 等
   - **"参谋"可换（`ANTHROPIC_BASE_URL` 等环境变量指向哪里，是用户自己的事），但"宰相"的权限边界由我们定**

6. **加测试**：至少证明"两个宰相都能被同一个太监派活并回传结果"

## 六、几个必须遵守的安全原则（不是建议，是硬要求）

1. **不代理登录**：AI 软件的登录一律由用户本人在自己电脑上完成，平台不碰凭据
2. **不存储明文凭据**：所有配对码、令牌**只存 SHA-256 哈希**
3. **网络默认出站**：电脑端主动连服务器，**不开入站端口**
4. **任务有时限**：每次授权最多 10 分钟，断网最多 15 秒停
5. **平台零收费**：不许加任何购买、充值、订阅、余额、积分、卡密、租期
6. **不做租赁**：设备只有 4 件事 —— 连接 / 远控 / AI 任务 / 传文件
7. **不许绕过平台风控**：用户明确说这是红线，任何"帮用户绕检测"的功能都不做
8. **现有文件的位置别乱移**：改之前先看清楚它在哪（有些文件在 `dist/win-unpacked/resources/device-bridge/`，不在 `src/`）

## 八、这个产品最终要长成什么样（给你方向感）

用户是**一个人干所有事**的创业者（"超级个体"）。他的真实一天：

- 早上 6:50 在被窝里，手机看一眼昨晚派的活干完没
- 7:40 地铁上，补一句话让电脑改个东西
- 12:10 吃饭时，把客户发的图转给电脑上的 AI 处理
- 15:00 开会，全程不看手机（因为只有出事才提醒）
- 23:40 躺下了，突然想到一个点子，说一句话，电脑连夜干
- 他有一堆机器（本地 + 美国 + 新加坡 + 日本 + 国内），**不可能天天坐在每台前面**

**所以产品的灵魂是：让人离开电脑，事情照样往前走。**

做的时候心里想着这句话。任何让用户"必须坐在电脑前"的设计，都是错的。
