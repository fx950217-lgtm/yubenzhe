# AI 群聊：一页看懂

日期：2026-10-12
你的问题：**「能不能同时把这些聊天的 ai 拉到一个群，同时并发，让 ai 自己回复」**

| 你说的 | 结论 |

## 「隔离」是两件事，我之前没说清楚

| | ① 可见性隔离 | ② 并发隔离 |
|---|---|---|
| 管什么 | **谁能看到**设备会话 | **一台机器同时跑几个任务** |
| 现在 | ✅ 已做（只你自己可见） | ❌ 写死 1 个 |
| 这次 | **不动** | **要改** ← 你说的就是这个 |

**你要打开的是 ②。打开它完全不会动到 ①。** 你说「隔离不是问题」是对的，我同意。

---

## ⭐ 你选的「每轮都点一下」救了整个方案

**如果不加刹车，多 AI 群聊会这样：**

```
你问一句 → A回复 → B看到 → B回复 → C看到 → C回复 → A又看到 → A又回复 → …
                    ↓
              无限循环，烧钱烧到天亮
```

**但你选了「每轮都要你点一下才继续」→ 这个循环根本形不成。**

```
你问 → A/B/C 各回一次（同时）→ 停 → 你点「继续」→ 再跑一轮 → 停
```

**你的手指就是刹车。这是最稳的设计。** 我另外还会加兜底（轮数上限 10 轮、总时长 30 分钟、一键全停）。

---

## ⚠️ 但有一个真正的问题：AI 进不了群

我查了数据库，群消息表是这么写的：

```sql
CREATE TABLE messages(
  sender TEXT NOT NULL REFERENCES accounts(id),  -- ⚠️ 发消息的必须是「账号」
  ...
);
```

**AI 没有账号 → 所以技术上插不进去。**

三条路，我推荐第一条：

| 路线 | 做法 | 评价 |
|---|---|---|
| **甲（推荐）** | AI 的回复显示成 **「我 · Codex · 我的电脑」** | ✅ 不用动核心表，干净 |
| 乙 | 给每个 AI 建个假账号 | ❌ 会污染好友列表、搜索 |
| 丙 | 改造群消息表 | ❌ 动核心表，风险大 |

**走甲的话，群里长这样：**

```
你（我）：帮我分析一下这个方案

我 · Codex 【我的电脑】：从工程角度，我建议…

我 · Claude 【我的电脑】：我补充一点不同的看法…
```

好处：能分清是哪个 AI 说的、不污染账号体系、**不用动核心表**。

---

## ⚠️ 还有一件你可能没想到的事

**你的电脑上有文件、项目、凭据。**

如果 AI 在一个**有别人在的群**里发言，就等于**可能把你电脑上的信息说出去**。

所以建议：**有好友的群，默认禁止 AI 发言**，你要用就手动开。

（你自己的单人群 → 随便用。）

## ⚠️ 顺便说一句大实话

这个是**目前所有任务里最难的一个**。原因：

- 要把「一台电脑一个任务」改成「多个任务同时跑」
- 涉及 **seq / 租约 / ack** 三个机制的隔离改造
- **这三处改错会导致消息错乱、丢失或重复**
- 而且**必须保持现有功能不受影响**

**所以我建议：先做 AI 注册表（上一个任务），再做这个。** 一步步来，别一起上。
