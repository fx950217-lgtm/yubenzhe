## 三、我审计发现的三个关键点

### ⚠️ 点 1：配对方向现在是反的

**现在的流程**：手机点「创建配对文件」→ 下载一个 JSON → **拿到电脑上打开**。

**你要的流程**：**电脑装好后显示机器码 → 手机输码 → 完成**。

**➡️ 这是方向翻转，不是小改动。** 地基（配对哈希、令牌、过期时间）**都能复用**，但要新增一条「电脑出码」的路径。

**机器码格式我建议**：`YBZ-7K2M-9QX4`（8 位分组，好念好输，避开 `0/O`、`1/I` 这种容易看错的）。

### ⚠️ 点 2：旧配对方式不能删

现有的「手机生成文件」方式**已经被测试覆盖**，而且对某些场景（比如电脑不方便显示界面）还有用。
**➡️ 我要求保留两条路，新的机器码是"再加上去"，不是"替换掉"。**

### ⚠️ 点 3：「不支持就标注」其实主要就是为云机准备的

你说「每个云端电脑、本地支持这些」——**这句话背后的真实场景是**：

| 机器类型 | 屏幕远控 | AI 任务 | 传文件 |
|---|---|---|---|
| **你自己的 Windows 电脑** | ✅ 支持 | ✅ 支持 | ✅ 支持 |
| **云端电脑**（Windows Server） | ❌ **通常没有桌面，不支持** | ✅ 支持 | ✅ 支持 |

**云机是 Server 系统，没有交互桌面** → 远控**天然做不了** → 所以要**明确标注"不支持"**，而不是点进去才失败。

**➡️ 这正是你要求的「不支持就标注」的最真实用途。** 而且云机的 AI 任务 + 传文件应该**照常能用**。

## 四、⚠️ 三个我必须先说的红线

**1. 不代登录 Codex** —— 安装包**不打包也不代登录** Codex。登录必须你本人扫码，这是它的安全机制。

**2. 安装包会被杀软报毒** —— 现在的配置是**不签名**（`signExecutable: false`）。
**➡️ 一定会被 Windows Defender 警告。** 我不会在界面或文档里写"无拦截"骗人。
要真去掉警告得买代码签名证书（要花钱），这是以后的事。

**3. 设备不能做成"好友"** —— 设备会话**只有你本人可见**，不能出现在群聊、朋友圈、不能分享。
这个边界必须服务端强制，不能靠前端藏。
