YBZ AI 注册表 — P4 实施边界（2026-10-12）

安装、登录、执行适配分开判断。Codex、Claude、WorkB、Ollama 的探测规则为数组；添加一种工具还需明确其服务端能力策略与安全执行适配，不能仅靠名称获得命令执行权。

固定端
只检查有限的 Windows 原生 exe 位置，不全盘搜索、不读取 AI 配置或凭据、不启动登录流程。每一种工具独立限时 5 秒；版本/登录命令用 shell:false，原始输出只在内存解析，不能上传或存入业务库。WorkBuddy GUI 文件存在只能证明安装线索，不能证明登录或 CLI 可用。非 Windows 当前不自动探测。
Codex 沿用 workspace-write、审批限制、stdin 任务输入及固定工作目录。Claude/WorkB 目前只做检测，没有已验证执行适配，明确显示不可执行；绝不把请求转交 Codex 冒充所选工具。
Ollama 只支持本机文字对话，不支持文件或工具。本人在电脑向导填写已安装模型，默认不选；不会自动下载、拉取模型或登录。HTTP 仅访问固定 127.0.0.1:11434 的 tags/show/generate，不读取代理或 OLLAMA_HOST，不接受重定向或云模型元数据。局域网/云端模型接入不属于这条设备适配。
本轮执行验收使用合成工具/模型替身，没有启动真实 AI 任务或消费第三方额度。检测通过不代表目标已完成。

可见性与存储
024 只新增 ai_channel_devices.providers、scanned_at 与 ai_channel_tasks.provider；保留原 provider='Codex' 历史列及历史迁移。scanned_at 是为区分真实检测时间与普通心跳而增加的字段。
上传字段有数量/长度/类型/标识白名单；名称和原因由服务端安全词表重建。exe 路径、模型名称、诊断原文、邮箱和凭据不进入注册表 API。电脑向导只得到裁剪后的公开状态；私有 exe 路径只在本机主进程和 worker 间传递。
电脑端仅将本人选定的本地模型名持久化；不把旧的 ready/登录/探测状态写回配置。重扫失败清空过时可执行状态。运行中不能改模型，包括排队 IPC 与启动的竞争情形；配置保存失败保留原值。
设备和任务仍须 ownedDevice 鉴权，他人访问 404。AI 未创建账号、好友或群成员。prompt 和回复沿用有界内存中转，不入数据库。

兼容与限制
旧连接器仅保留 Codex 兼容状态，旧任务 provider 默认 codex，旧幂等请求摘要可继续识别。新的 provider 参与幂等摘要；改变工具不能复用原请求编号执行第二次。
本批仍每台电脑单任务，P7 再实现并发。手机显示与入口在 P5/P6 接入，不能以 P4 后端完成声称手机已完整适配。
缺少可用工具时继续保留消息、钱包、机器码和远控能力；工具执行状态不能替代屏幕能力检测。

本机启动
node tongban/build.mjs
node scripts/start-ultimate-review.mjs
审核 http://localhost:18934/；状态目录 ../ybz-ultimate-review-20261012 为本轮独立合成数据。真实已配对电脑连接器仍只允许可信 HTTPS，不能为本地预览放宽该限制。
独立脚本可在原 --workspace/--state/--runtime-dir 参数基础上指定 --ollama-model，但必须是已经本机安装并通过校验的模型名。
