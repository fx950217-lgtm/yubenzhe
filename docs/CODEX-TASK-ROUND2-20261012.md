## 【Q1】设备直连（⚠️ 本轮主体 · 已按新方向重写）

### Q1.1 ⚠️ 先有两个硬限制必须解决（**动手前先出调研结论**）

我实测了本机环境，发现两件事会直接挡住「远程桌面直连」：

#### 限制 1：Windows 家庭版**没有**远程桌面服务端

| 版本 | 能当被控端吗 |
|---|---|
| Windows **家庭版**（Home） | ❌ **不能**（只能去连别人，不能被连） |
| Windows **专业版 / 企业版** | ✅ 能 |

**这里实测的环境是 Windows 10 Pro**（`EditionID=Professional`），可以当被控端。

**➡️ 要求**：连接器要探测版本，**家庭版必须明确告诉客户「你这台不能被远程」**，不能让客户装完才发现。

#### 限制 2：客户端版 Windows 的远程桌面是「**单会话**」

Windows 专业版当被控端时，**第二个人连进来会把第一个人踢下去**。
**➡️ 用户要的「1 人控制 + 多人同时看」，在原生远程桌面下做不到。**

**两条出路 —— Codex 先调研，给结论 + 建议，再动手**：

| 方案 | 说明 |
|---|---|
| **甲** | **RDP Shadow（影子会话）**：管理员「影子」进同一会话，多人可同看 |
| **乙** | 引入支持多客户端的 **VNC 类工具**（TightVNC / UltraVNC 等） |
| 丙 | 回退到平台中转画面 —— **用户已明确排除** |

**⚠️ 本项必须先出结论，不要闷头选一个实现。报告里要写清：选哪个、为什么、替代方案是什么。**

### Q1.2 设备端：连接器要探测并上报

**改造 `yubenzhe-deploy/device-bridge/capabilities.mjs`**（它已有探测框架，扩字段即可）：

| 新增探测项 | 用途 |
|---|---|
| 系统版本（家庭版 / 专业版） | 判断能不能当被控端 |
| 远程桌面是否已开启 | 没开就给开启指引 |
| 远程桌面端口 | 默认 3389，可能被改过 |
| 本机局域网 IP | 同网段设备可连 |
| **公网可达地址** | 外网可连；**探测不到就让客户自己填** |
| 当前登录用户名 | 连接时要用 |

**⚠️ 不上报屏幕帧** —— 直连模式下画面根本不过平台。
**⚠️ 探测要沿用既有纪律**：独立超时、`shell:false`、失败不猜、不读凭据文件。

### Q1.3 平台侧：只存连接信息

**新迁移** `026-device-direct-connect.sql`（**编号先核对 `MIGRATIONS` 数组末尾**）：

需加字段（示例，按实际设计调整）：
- `rdp_host` / `rdp_port` / `rdp_username`
- `rdp_password_ciphertext` + `password_iv` + `password_tag`
- `rdp_password_updated_at` / `rdp_expires_at`

**⚠️ 密码必须加密存储**，复用现有 `decodeDesktopCredentialKey` 的 `aes-256-gcm` 模式与 AAD 绑定习惯。
**⚠️ 只增不删，不改 001–025。**

### Q1.4 ⚠️ 安全要求（用户选了「谁都能看」，按此执行但必须加固）

用户明确选择「**只要知道连接信息就能看**」。**尊重该决定**，但以下五条是**强制**的：

| # | 要求 | 理由 |
|---|---|---|
| 1 | **密码必须短时效**（建议 30 分钟自动失效/轮换） | 否则泄露一次 = 永久敞开 |
| 2 | 页面**醒目警示**：「拿到这段信息的**任何人**都能连接你的电脑」 | 客户知情 |
| 3 | 提供**一键失效**（立即换密码 / 关远程桌面） | 发现异常能马上断 |
| 4 | ❌ **不得提供「永久密码」选项** | 风险不可控 |
| 5 | ❌ 连接信息**不得进日志、通知、朋友圈** | 防意外扩散 |
