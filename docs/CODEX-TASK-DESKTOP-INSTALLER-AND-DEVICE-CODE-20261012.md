## 一、本轮五件事（按优先级）

### 1. 🟢 P0：电脑版安装工具（用户明确要求）

**用户原话**：
> 「让他开发电脑版本的安装工具」

**要求**：做一个 Windows 安装程序，让用户**双击装好**，不用敲命令。

**要做的**：

| 组件 | 说明 |
|---|---|
| **安装器** | 复用 `yubenzhe-desktop/` 的 electron-builder 配置（`package.json` 已有 NSIS 配置、`icon.ico`、中文语言包） |
| **捆绑内容** | 设备连接器（节点 + `agent.mjs` + `ai-channel.mjs` + `codex-runner.mjs`） |
| **首次运行向导** | ① 自动生成机器码并显示 ② 提示"在手机 ybz 输入这个码" ③ 检测本机能力并上报 |
| **开机自启（可选）** | 托盘常驻，右键可停止 |
| **不捆绑 Codex** | ⚠️ **不打包也不代登录 Codex**（登录必须本人完成） |

**⚠️ 关键约束**：
- `allowElevation: false`（现有配置已设）→ **不需要管理员权限**
- `signExecutable: false`（现有配置）→ ⚠️ **会被 Windows Defender 警告**，要如实告知，不要宣传"无拦截"
- **不要**把 Codex 或任何 AI 塞进安装包（体积 + 合规）
- 安装包要能**独立运行**（用户没装 Node 也能用）

### 4. 🟡 P1：机器码配对（⭐ 用户的核心要求）

**用户原话**：
> 「链接方式要电脑先安装 ybz 生成 ybz 机器码，只要在手机设备输入这个码就可以操作这台电脑」

**⚠️ 这是配对方向的翻转**：

| 现在（反向） | 改成（用户要的） |
|---|---|
| 手机点「创建配对文件」→ 下载 JSON → 电脑选文件 | **电脑安装后生成机器码 → 手机输码 → 完成** |
| `devices/pair` 由手机生成 `pairToken`（43 字符） | 由**电脑生成短码**，手机提交 |

**要做的**：

| # | 内容 |
|---|---|
| 1 | **电脑端生成机器码**：安装后自动生成，显示在向导 + 托盘菜单可再看 |
| 2 | **机器码格式**：⚠️ 建议 **8 位分组**（如 `YBZ-7K2M-9QX4`），**易读易输**；区分 `0/O`、`1/I` |
| 3 | **服务器新增 `POST /api/device-bridge/claim`**：电脑上报机器码 → 手机带机器码兑换 |
| 4 | **手机端新增「输入机器码」界面** |
| 5 | **兑换后自动进设备列表 + 聊天列表** |

**安全要求（一条不能少）**：

| # | 约束 |
|---|---|
| 1 | **机器码有效期 ≤ 10 分钟**（沿用现有 `pair_expires` 思路） |
| 2 | **一次性**（用掉即失效，`pair_hash` 置空） |
| 3 | **只存哈希**（照抄现有 `pair_hash` / `token_hash` 做法） |
| 4 | **生成频率限制**（防暴力猜码：同 IP / 同账号每分钟 ≤ 5 次尝试） |
| 5 | ⚠️ **机器码 ≠ 长期凭据**：兑换后服务端签发长期 token（沿用 `secret()` 43 字符），机器码随即作废 |
| 6 | **失败的尝试要计数并延迟**（防枚举） |
| 7 | **电脑端可随时重新生成**（旧码立即失效） |

**⚠️ 保留旧方式**：现有的「手机生成文件 → 电脑打开」**不要删**（向后兼容，且已被测试覆盖）。

### 5. 🟡 P1：设备能力检测与标注（用户明确要求）

**用户原话**：
> 「然后可以用电脑打开桌面是否支持，不支持就标注，每个云端电脑，本地支持这些」

**理解为**：**电脑要上报自己"支持哪些功能"，手机列表里逐项标注支持/不支持。**

**要做的**：

| # | 内容 |
|---|---|
| 1 | **电脑端检测并上报能力**（新增能力字段） |
| 2 | **手机设备卡片逐项标注**：✅ 支持 / ⚠️ 部分支持 / ❌ 不支持 |
| 3 | **不支持的入口要禁用 + 写明原因**，不要点进去才报错 |

**能力清单（建议上报）**：

| 能力 | 怎么检测 | 不支持时怎么标注 |
|---|---|---|
| **屏幕远控** | 有交互桌面？（`desktop.ps1` 能否启动） | 「无图形界面，不支持远控」 |
| **AI 任务** | `codex.exe` 是否存在 + `codex login status` | 「未装 Codex / 未登录」 |
| **文件收发** | 运行时目录可写？ | 「文件通道未启动」 |
| **开机自启** | — | 「需手动启动」 |
| **是否无头（Server 核心）** | 检测桌面会话 | ⭐ **这正好对应"云端电脑"** |

**⚠️ 与云端电脑的关系**：
- 云端电脑（Windows Server）**通常没有交互桌面** → 屏幕远控**不支持**，要**明确标注**
- 但 AI 任务 + 文件**支持**（纯命令行）→ **这两项要能正常用**
- **➡️ 这就是"不支持就标注"的真实场景**，也是用户说"每个云端电脑、本地支持这些"的意思

**实现要求**：
- 能力字段加在**现有** `status` 上报里（`ai-channel.mjs` 第 113 行的 `status` 对象）
- 服务器**新增能力列**（迁移 `022`）
- 前端 `personal-devices.js` 卡片里**逐项渲染**

**要做的**：

**如果实现成本高**：**可以先只做"设备在消息列表里显示一个入口"**，
不必真的做成完整的社交会话对象。**优先保证不破坏现有社交边界。**
