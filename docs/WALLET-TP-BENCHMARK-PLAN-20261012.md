# 钱包对标 TP 钱包：改造方案

日期：2026-10-12
性质：**改造方案 + 给 Codex 的开发任务书**
范围：**只要主流链 + DApp 功能，简单、方便**
⚠️ 先读第零节和第三节的红线，再读改造清单。

---

## 零、先审计现状（我实读代码得出，不是猜）

### 0.1 现在钱包有什么

| 已有能力 | 位置 | 状态 |
|---|---|---|
| 自托管钱包（本地加密 vault） | `tongban/src/wallet.js`（31.4KB） | ✅ 可用 |
| 创建 / 助记词 / 私钥 / Keystore 导入 | `wallet.js` L154-190 | ✅ 四路导入齐全 |
| 观察钱包（watch-only） | `wallet-watchlist.js` | ✅ |
| **原生转账** | `wallet.js` L265-460 | ✅ 但**只支持 BSC 测试网 97** |
| 手续费估算 | `wallet-fees.js` | ✅ 按实际 gasUsed×gasPrice |
| 交易记录（本地） | `wallet.js` L384-404 | ✅ 本地存 localStorage |
| 合约交互（等额分发） | `wallet.js` L476-520 | ⚠️ **只针对自家分发合约** |
| 钱包锁定 / 自动超时 | `wallet.js` L67-107 | ✅ |

### 0.2 ⚠️ 现在有四个硬限制（这是本改造要解决的）

| # | 限制 | 代码证据 |
|---|---|---|
| **1** | **只支持 BSC 测试网（chainId 97）**，主网都不行 | `wallet.js` L10 `chainId: 97`；L50 vault 校验 `vault.chainId !== 97` 即报错；L247 `BigInt(chain) !== 97n` 直接拦交易 |
| **2** | **13 处硬编码 `chainId: 97`** | L50/62/348/379/389/434/441/450/495/512… |
| **3** | **不能向合约地址转账** | L289 `code !== '0x'` 就抛「首版仅支持向普通钱包地址转账」 |
| **4** | **没有 DApp / WalletConnect** | 全项目搜 `walletconnect` / `eth_requestAccounts` → **零结果** |
| **5** | **没有「发现」DApp 入口** | 只有自家分发合约的专用界面 |

### 0.3 ⚠️ 还有一个更重要的：RPC 白名单锁死

`service-defaults.json`：
```json
"rpcUrls": [
  "https://bsc-testnet-dataseed.bnbchain.org",
  "https://bsc-testnet.bnbchain.org"
]
```
且 `wallet.js` L306 有 **方法白名单**：
```js
if(!READ_METHODS.has(method)) throw fail('不支持该链上查询。','RPC_METHOD_BLOCKED');
```

**➡️ 这是安全设计（防任意 RPC 调用），但也是多链的障碍。** 改造时必须**扩展白名单**而不是删掉它。

## 一、TP 钱包的能力拆解（我查了官网）+ 我们的取舍

### 1.1 TP 钱包有什么（官方页面核实）

| TP 的能力 | 我们要不要 |
|---|---|
| 支持 30+ 公链（BTC/ETH/BSC/TRON/Polygon/Solana/Cosmos/Polkadot…） | ⚠️ **只取主流 EVM 链**（见 1.2） |
| **内置 DApp 浏览器**（访问任意 DApp 链接） | ✅ **要**（核心） |
| **WalletConnect**（连接外部 DApp） | ✅ **要**（核心） |
| 一站式 DApp 商店（发现热门 DApp） | ✅ 要（简化版，只放白名单） |
| 跨链 Swap / 内置桥 | ❌ **不要**（风险高，见 3.2） |
| 法币入金（信用卡买币） | ❌ **不要**（要牌照） |
| Staking / 流动性挖矿 / 理财 | ❌ **不要**（要合约，风险高） |
| NFT 市场 | ❌ 不要 |
| 硬件冷钱包 | ❌ 不要 |
| 多签钱包 | ❌ 不要 |
| TP Card（用币支付） | ❌ 不要 |
| 限价单 | ❌ 不要 |

### 1.2 ⭐ 「主流链」我建议就这四条

**用户要「只要主流链」。我的选择标准：① EVM 兼容 ② 用户量大 ③ 一条 RPC 就能跑。**

| 链 | chainId | 原生币 | 为什么选 |
|---|---|---|---|
| **BNB Chain 主网** | `56` | BNB | 用户主力，已有基础 |
| **Ethereum 主网** | `1` | ETH | 最大生态 |
| **Polygon** | `137` | POL | 便宜、DApp 多 |
| **Arbitrum One** | `42161` | ETH | L2 主流 |

**⚠️ 明确不做的链**：
- **BTC** —— 非 EVM，**需要完全不同的签名/UTXO 逻辑**，工作量等于再做一个钱包
- **TRON / Solana / Cosmos / Polkadot / EOS** —— 都**非 EVM**，同上
- **测试网 97** —— **保留**（现有功能都跑在它上面，删了就全废）

**➡️ 所以是「4 条主网 + 1 条测试网」。这就是「简单」。**

## 二、改造清单（分三块）

### 2.1 🟢 A 块：多链支持（把 13 处硬编码拆掉）

**目标**：从「只 BSC 测试网」变成「4 主网 + 1 测试网可切换」。

| # | 改哪里 | 怎么改 |
|---|---|---|
| **1** | 新建 `tongban/src/chain-registry.js` | 链定义集中一处：chainId / 名称 / 原生币 / RPC 列表 / 浏览器地址 / 图标 |
| **2** | `wallet.js` L10 的 `NETWORK` 常量 | 改成从注册表读当前选中链 |
| **3** | `wallet.js` L50/62 vault 校验 | ⚠️ **vault 不要绑 chainId** —— 钱包地址跨链是同一个，这是**设计缺陷**。保留字段做兼容，但校验放宽 |
| **4** | `wallet.js` L247 `assertChain` | 改成「必须匹配当前选中链」而不是「必须等于 97」 |
| **5** | L348/379/434/441/450/495/512 等 9 处 `chainId: 97` | 全改成 `chainId: activeChain.id` |
| **6** | L289「不支持合约地址」 | ⚠️ **这个限制对 DApp 是致命的**，见 2.3 |
| **7** | `service-defaults.json` 的 `rpcUrls` | 改成按链分组的对象 |
| **8** | `wallet.js` L306 RPC 方法白名单 | **保留并扩展**，不要删 |

**⚠️ 迁移注意**：现有用户 vault 里存的是 `chainId: 97`，**不要因为改造就让老钱包打不开**。
→ 做法：读取时**兼容 97**，写入时用新结构。

**界面要求**（对齐 TP 的简单感）：
- 顶部那个 `BSC 测试网 ⌄` 按钮（`app.js` L71 已存在）→ 点开**链切换列表**
- 切换时**明确提示"地址不变，资产按链分开显示"**（这是新手最困惑的点）
- 每条链显示：名称 + 原生币余额 + 是否已添加

### 2.2 🟡 B 块：DApp 浏览器 + WalletConnect（核心）

**用户明确要「dapp 功能」。**

**(1) 内置 DApp 浏览器**

| 要求 | 说明 |
|---|---|
| 入口 | 底部「发现」Tab 或钱包页内一个入口（**建议放钱包页内**，不占主导航） |
| 形式 | **白名单 DApp 列表**（不是任意输入网址） |
| 白名单内容 | Uniswap、PancakeSwap、OpenSea 等**头部协议**（对齐 TP 的"一站式 DApp 商店"） |
| 打开方式 | ⚠️ **手机端用系统浏览器打开**，不要在 App 内嵌 WebView（见 3.3） |
| 危险提示 | 首次打开 DApp 前，显示一次安全提示 |

**(2) WalletConnect**

**这是「DApp 能用」的关键** —— 让用户在手机 DApp 或网页 DApp 里，扫码/深链连接到我们的钱包签名。

| 要做 | 说明 |
|---|---|
| 库 | ⚠️ **需确认**：`@walletconnect/*` 的当前版本与体积，**不要凭记忆写版本号** |
| 能力 | `eth_sendTransaction` / `personal_sign` / `eth_signTypedData_v4` |
| ⚠️ **签名前必须展示** | **金额、收款方、链、gas、调用的合约方法** —— 只显示"请求签名"是绝对不行的 |
| 会话管理 | 列出已连接的 DApp，可随时断开 |
| 限制 | 单次会话时长上限；单个 DApp 请求频率限制 |

**⚠️ 这是整个改造里风险最高的部分**（等于把签名能力开放给外部页面）。见 3.4。

**(3) 合约交互（去掉 L289 的限制）**

要支持向合约地址发交易，必须：
- 解析 `data` 字段（至少能显示**调用的方法名和参数**）
- **不能盲签** —— 解析不出来的，明确显示「无法识别的方法」+ 强警告
- 保留现有的 `approve` 无限授权警告（如果有）

### 2.3 🟡 C 块：体验简化（用户要「方便」）

| # | 改进 | 说明 |
|---|---|---|
| 1 | **资产列表按链分组** | 现在只有一个 tBNB 余额 |
| 2 | **代币自动发现** | 按链拉取常见代币余额（对齐 TP「代币自定义添加」） |
| 3 | **收款码** | 已有 `receive` 图标，确认可用 |
| 4 | **交易记录跨链合并** | 现在 `getRecords` 过滤 `chainId===97`（L389），要改 |
| 5 | **Gas 三档选择**（慢/标准/快） | 对齐主流钱包习惯 |
| 6 | **地址簿** | 常用地址，减少输错 |

**⚠️ 保持现有的好设计不要改**：
- 密码强度校验（10–256 位 + 字母数字）
- 交易预览过期机制（`PREVIEW_EXPIRED`）
- 「还有待核实交易」防重复签名（L315）
- 私钥/助记词**永不上传**
- 钱包锁定 + 自动超时

## 三、⚠️ 红线（这一段最重要，必须读完）

### 3.1 ⚠️ 法律与合规：不要碰法币

**TP 有「信用卡买币」** —— **我们绝对不能做**。
买币 = 支付/汇兑业务 → 需要牌照。**上一轮已经确认过项目有明确的合规红线。**

**➡️ 界面上不出现任何"买币""入金""充值"字样。**

### 3.2 ⚠️ 不要做跨链桥和 Swap

| 为什么 | 说明 |
|---|---|
| 桥是**被盗重灾区** | 跨链桥历史损失以十亿美元计 |
| 需要**流动性** | 你要先垫资金池 |
| 需要**合约审计** | 项目现状：`contracts/README.md` 明确写「**当前合约未经独立审计**」 |
| 出问题**你赔** | 用户资产损失直接找你 |

**➡️ 用户说「简单」，砍掉桥和 Swap 正好符合。**

### 3.3 ⚠️ DApp 浏览器：不要内嵌 WebView （**双红线：安全 + 上架**）

**风险一（安全）**：内嵌浏览器里，**恶意 DApp 可以窃取页面上下文**，甚至伪装 UI 骗签名。

**风险二（上架）**：App 内嵌 WebView 打开任意 DApp，审核员会质疑内容可控性。
**➡️ 详见 `WALLET-COMPLIANCE-REVIEW-20261012.md`（2026-10-12 合规审查）。**

**➡️ 做法**：DApp 用**系统浏览器**打开，通过 **WalletConnect 深链**回到钱包签名。
**好处**：我们只负责"签名确认页"，恶意页面碰不到私钥环境。

**⚠️ 附加要求（来自合规审查）**：
- DApp **只放白名单**，不做任意网址输入框
- 界面**不出现**「买币 / 入金 / 充值」
- **不做**「邀请返利送币」「完成任务送币」（撞 Apple 3.1.5(v)）
- **不能让钱包解锁 App 高级功能**（撞 Apple 3.1.1）

### 3.4 ⚠️ WalletConnect 是最大风险点（必须做这几条）

一旦接了 WalletConnect，**任何 DApp 都能请求签名**。必须：

| # | 约束 | 理由 |
|---|---|---|
| 1 | **逐笔人工确认**，绝不允许"批量/自动签署" | 防被薅 |
| 2 | **显示完整交易参数**（to/value/data/gas/链） | 防盲签 |
| 3 | **`eth_sign`（盲签任意哈希）必须禁用** | ⚠️ 这是最危险的签名类型，**永远不要开放** |
| 4 | **`eth_signTypedData` 要显示域名和内容** | 防钓鱼签名 |
| 5 | **会话可随时断开 + 超时自动断开** | 减少暴露窗口 |
| 6 | **只连白名单 DApp**（可选，但强烈建议） | 降低风险 |
| 7 | **明确提示"签名后资产可能被转走"** | 用户教育 |
| 8 | 私钥/助记词**永不经过 WalletConnect** | 底线 |

### 3.5 ⚠️ 主网 = 真金白银（必须让用户确认）

**现在的钱包是测试网玩具**（tBNB 无价值）。**一旦上主网**：
- 用户**真的会丢钱**
- 你的代码 bug **直接造成资产损失**
- `contracts/README.md` 说合约**未审计** → 主网合约交互要格外小心

**➡️ 我建议分两步**：
1. **第一步：只放开「主网转账」**（发送原生币 + 代币），**不放开合约交互**
2. **第二步：合约交互 + WalletConnect 确认无误后，再放开**

## 八、一句话总结

> **TP 的 30+ 链、桥、Swap、买币、Staking、NFT 全都不做。**
> **只抄它两样最有价值的：① 多链（取 4 条主流 EVM 主网）② DApp（白名单 + WalletConnect）。**
> **现在的钱包只支持 BSC 测试网、13 处硬编码 97、不支持合约地址转账、没有 DApp。**
> **⚠️ 最大风险是 WalletConnect（等于把签名开放给外部页面），必须逐笔确认 + 禁用 `eth_sign` + 显示完整参数。**
> **⚠️ 主网上线 = 真金白银，建议先只放开转账，合约交互等稳了再说。**
