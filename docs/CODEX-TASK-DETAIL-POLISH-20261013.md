## 【A 组】对齐原型与实现（诚实性优先）

> 目的：`design/ybz-mobile-ui.html` 里画的东西，和真实实现必须一致。**界面不许出现"看起来能用、实际是空的"入口。**

### A1. 钱包：撤掉三个"尚未接入"的分类 tab

**现状证据**（已核实）：
```js
// tongban/src/wallet-home.js:5
const tabs=[['assets','资产'],['defi','DeFi'],['nft','NFT'],['authorizations','授权']];
// tongban/src/wallet-home.js:2
const unavailable={defi:['DeFi','当前没有接入 DeFi 协议…'],nft:['NFT','…'],authorizations:['授权','授权扫描和撤销尚未接入…']};
// tongban/src/wallet-home.js:17
panel?`<section class="wallet-unavailable" role="status"><h2>${panel[0]}尚未接入</h2>…`
```

**Codex 做得很诚实**（明确写"尚未接入"），但用户翻原型会以为有。

**要做**：
- **把 `DeFi` / `NFT` / `授权` 三个 tab 从 tab 栏移除**（只留 `资产`）
- `unavailable` 对象和 `panel` 分支**保留**（将来接入时直接启用）
- 移除后用注释标明「预留：DeFi / NFT / 授权，接入后恢复 tab」

**为什么撤而不是留**：留着三个点了就说"没接入"的 tab，用户会以为是坏了。撤掉，界面干净。

**验收**：
1. 钱包页 tab 栏只有「资产」一个（或「资产 | 转账记录」两个，见 A3）
2. `defi` / `nft` / `authorizations` 三个 key 仍在代码里，但**不可从 UI 到达**
3. 撤掉后无 JS 报错（`chain-defi` / `chain-nft` / `chain-authorizations` 三个 action 的调用点要一并处理）
4. 前端测试全绿

### A2. 钱包：行情改为"明确标注未接入"，不许留半个假数字

**现状证据**：
```js
// tongban/src/wallet-home.js:17
<small>行情与涨跌幅未接入</small>
<small>测试资产不估值</small>
```

**这个写法是对的**（诚实）。**本轮只需要确认一致性**：
- 确保**没有任何地方**显示假的 `$752.12` `-0.59%` 之类数字
- 原型里画了行情是为了看版式，实现里**保持现在的诚实标注即可**

**验收**：
1. 全项目搜 `0.59` / `752` 等原型里的示例数字 → **实现代码零命中**
2. 行情位置显示「行情与涨跌幅未接入」

> ⚠️ **如果要接真实行情**：必须先确认数据源、且**只显示不交易**。**本轮不做**，等用户单独拍板。理由：接行情 = 引外部依赖 + 可能触发金融展示合规，而"测试资产不估值"目前是最安全的。

### A3. 钱包：多钱包切换 —— **这是本组唯一的大件**

**现状证据**（已核实）：
```js
// tongban/src/app.js:248  openWalletManagement()
showModal('本机钱包管理','<p class="address">'+address+'</p>…<button data-local-export>导出加密备份</button><button data-local-delete>删除本机钱包</button>')
```
→ **只有单钱包**：管理页只能"导出备份"和"删除"，**没有钱包列表、没有新建第二个、没有切换**。

而原型画了「**钱包 1 ▾**」可切换。

**要做**（二选一，**推荐甲**）：

| 方案 | 做法 | 工作量 |
|---|---|---|
| **甲（推荐）** | **实现多钱包**：本机支持多个钱包，钱包页顶部可切换，管理页可新建/重命名/删除 | 中 |
| 乙 | **撤掉原型的切换箭头**，只留一个钱包名（不可点） | 5 分钟 |

**➡️ 我替你定了：走甲**。理由：多钱包是钱包类 App 的**基础能力**（TP/小狐狸都有），用户明确说"钱包是客户必备"。

**甲方案具体要求**：
1. **本机存储多个 vault**（现在 `wallet.js` 是单 vault，需改成"钱包集合 + 当前选中"）
2. **每个钱包独立**：独立助记词/私钥、独立地址、独立备注名
3. **切换不丢状态**：切换后余额、记录、当前链都跟着切换
4. **删除某钱包**：不影响其他钱包；链上资产不受影响（写清提示）
5. ⚠️ **密钥仍只存本机**（`aes-256-gcm` 加密，不得上传）
6. ⚠️ **不给钱包起"真名"给服务器看**：备注名只存本机

**迁移**：如需新表/新列 → `029-wallet-collection.sql`（见迁移表）

**验收**：
1. 能创建 ≥2 个钱包，各自地址不同
2. 顶部切换后，余额/记录/资产列表全部跟着切
3. 删除钱包 B，钱包 A 完好
4. 密钥**零上传**（抓包或代码审查证明）
5. 切换后有测试覆盖（≥5 条）
6. 老用户（单钱包）升级后**不丢钱包**（迁移兼容）

### B3. 撤回消息

**现状证据**：`live-social.js` 只有 `cancel-send`（取消**发送重试**，`live-social.js:445` 明确写"这不会撤回服务器可能已经收到的消息"）→ **没有真正的撤回**。

**要做**：

- ⚠️ **AI 消息不可撤回**（代发的，语义不同）—— 或按代发者本人处理

**验收**：
1. 2 分钟内可撤回，超时按钮消失
2. 撤回后双方显示一致（不留原文）
3. 撤回不产生新的未读
4. 测试覆盖 ≥ 3 条

**验收**：
