【为什么做这个】
产品要服务两类用户：
  A. 有自己电脑的人 → 装连接器 → 手机和电脑关联 → 手机聊天框控制电脑
  B. 没电脑的人 → 付费开云机 → 云机上装好环境 → 同样连到手机聊天框

两条路径的终点是同一个（聊天框 + 远控）。路径 A 零边际成本且已完成一半
（设备配对、远控已在 dev.10 上线），所以先做 A。

本任务做路径 A 的三件核心事：
  1. 把连接器做成真正的「一键安装」
  2. 内置 AI 推荐问卷（帮用户决定装哪个 AI）
  3. 实现「一键装 AI」（先从能全自动的 Ollama 开始）

【怎么用这份文档】
从「任务书开始」到「任务书结束」整段复制，一次给 Codex，等它跑完看报告。

`启动连接器.cmd`、`停止连接器.cmd`。用户需要解压 + 手动跑 cmd，**不是一键**。

目标：让「有电脑的用户」在手机上看一个链接，电脑上打开就完成安装。

1.1 在手机上增加「安装到我的电脑」引导页

  `https://<origin>/install-agent?pair=<pairToken>`

  「如果 Windows 弹出'是否允许修改'，请点'是'。这是安装必需的一步。」

2.2 新增推荐接口

```
GET /api/devices/ai-catalog
  → 200 { tools: [...] }   （只返回元信息，不含任何密钥）

POST /api/devices/ai-recommendation
  body: { purpose, budget, deviceProbe }
  → 200 { recommended: [{ toolId, reason }], explanation }
```

推荐逻辑（纯规则，不调模型）：
- `purpose`：`'chat'` | `'writing'` | `'automation'`（让 AI 帮我操作电脑）
- `budget`：`'none'` | `'low'` | `'unlimited'`
- `deviceProbe`：`{ ramGb, diskFreeGb, os }`

规则表（照这个实现，不要自己发明）：
```
budget='none'                    → ollama（若 ramGb >= 8），否则提示配置不足
budget='low' + purpose='chat'    → deepseek
budget='low' + purpose='writing' → deepseek
budget='low' + purpose='automation' → codex-cli
budget='unlimited' + automation  → claude-code
budget='unlimited' + 其他        → codex-cli
```
- `ramGb < 8` 时，`ollama` 不推荐（本地模型跑不动），改推荐 web 版
- 返回值里的 `reason` 必须是**人话**，例如：
  「你的电脑内存 16GB，跑本地小模型没问题。它完全免费，而且不用注册账号。」

第三部分：一键安装 AI（先做 Ollama）
-----------------------------------------------------------

⚠️ 这是全场最敏感的功能。安全要求比功能要求更重要。

3.1 新增安装任务接口

```
POST /api/devices/:id/install
  body: { toolId, requestId, proof }
  → 202 { jobId }
  → 400 如果 toolId 不在 ai-catalog.json 里，或 autoInstall !== true

GET /api/devices/:id/install/:jobId
  → 200 { status, log, error }
```

要求：
- **幂等**：复用项目现有的 requestId 模式（参考 `workbench-service.mjs` 的 `command()`）
- **强验证**：参考 `desktop-service.mjs` 里 `proof(...)` 的用法（单次强验证）
- **只允许白名单工具**：`toolId` 必须存在于 `ai-catalog.json` 且 `autoInstall===true`
  - 白名单以外一律 400 `TOOL_NOT_INSTALLABLE`
- **不允许传任意命令**：安装命令**由服务端写死**在代码里，
  客户端**只能传 toolId**，绝不能传命令行
  → 这条是防 RCE（远程命令执行）的关键，**必须做到**

3.2 连接器侧执行安装

在 `device-bridge/agent.mjs` 里增加处理安装指令的分支。

Ollama 安装实现（Windows）：
- 官方安装包地址写死在代码里（不要从服务端下发 URL）
- 下载到临时目录 → **校验官方签名的可用性**（至少校验文件大小/哈希，如果拿不到官方哈希，
  就在代码注释里说明这个限制）
- 静默安装（Ollama 的 Windows 安装包支持静默参数，实现时先确认）
- 安装后跑 `ollama pull <小模型>` 验证可用
- 每一步的进度写入日志，供手机端轮询显示

3.3 安全红线（**这一节任何一条都不能违反**）

1. ❌ **绝不能执行客户端传来的任何命令行字符串**
2. ❌ **绝不能从服务端下发的任意 URL 下载可执行文件**
3. ❌ 安装动作**必须**有上限：单设备同时只允许 **1 个**安装任务
4. ❌ 安装任务**必须**有超时（建议 15 分钟），超时后终止并记录
5. ❌ **不得**提权（如果安装需要管理员权限，如实提示用户手动操作）
6. ✅ 所有安装动作**必须**写审计日志（谁、何时、设备 ID、toolId、结果）
7. ✅ 手机端界面上**必须**在安装前显示：
   「即将在你的电脑上安装 XXX。安装来源：官方。你可以随时取消。」

3.4 安装前的用户确认（防安全软件拦截）

安装前，手机端显示一个引导（文字即可，后续可换截图）：
```
如果电脑上弹出安全提示，请选择「允许」或「仍要运行」。
常见情况：
· Windows Defender → 点「更多信息」→「仍要运行」
· 360 / 电脑管家     → 点「允许本次操作」
如果被拦截了，安装会失败，你可以重试。
```
