# 远程云端电脑 · 完整规划
**版本**：V1 · 2026-10-11
**定位**：本文回答一件事 —— 客户怎么在我们的 App 上一键开通一台云端电脑，拿到密码，然后**哪怕卸载我们的 App，也能用官方客户端继续登录**。

---

## 0. 先把你的需求翻译成人话

你说的三句话，其实是三个独立的技术要求：

| 你说的话 | 真实含义 | 行业术语 |
|---|---|---|
| 「客户一键在我们平台上开通」 | 客户只点一个按钮，背后所有的买机器、装系统、开账号，我们全代办了 | **API 化开通（Provisioning API）** |
| 「保留密码」 | 密码给客户，不是我们拿着。客户不依赖我们就能进 | **凭据归用户（BYO Credential）** |
| 「哪怕不使用我们的平台，一台电脑也可以登陆，远控那些桌面」 | 客户拿到的是一台**标准的**电脑，不是只能在我们 App 里看的画面 | **可迁移 / 不锁定（Portable / No Lock-in）** |

**这三条的核心意义**：我们卖的是「省事」，不是「控制权」。
客户随时可以走，但因为我们省事，他不走。
—— 这一点和你做钱包的理念**完全一致**（自托管、密钥归用户）。这也是你唯一能讲得通的故事。

## 1. 服务商对比：谁真的支持「一键开通 + 白牌 + 给用户标准凭据」

### 结论先行

| 服务商 | 能否 API 一键开通 | 能否白牌 | 用户拿到的凭据能否脱离我们 | 单台月成本 | 一句话结论 |
|---|---|---|---|---|---|
| **AWS WorkSpaces** | ✅ 完整 API | ⚠️ 需自建前端 | ✅ 标准 RDP/DCV | $16.8 – $220 | **技术最成熟，但 API 权限申请有门槛** |
| **阿里云无影** | ✅ 有 API + 省级代理 | ✅ 代理可贴牌 | ✅ 无影官方客户端全平台 | ¥ 几十–几百 | **国内最快，但要求中国公司资质** |
| **腾讯云云桌面** | ✅ 有 API | ⚠️ 需代理授权 | ✅ 腾讯官方客户端 | ¥ 几十–几百 | 类似无影，代理体系更封闭 |
| **自建 VM 编排** | ✅ 完全自控 | ✅ 完全白牌 | ✅ 自己发 RDP 凭据 | $5 – $20 | **最便宜最可控，但你要自己维护** |

### 1.1 AWS WorkSpaces（技术首选，代码可跑）

**为什么选它**：它是全场唯一一家把「开通一台云电脑」做成了**标准 REST API** 的服务商。调用它就像调用支付 API 一样，是代码能力。

**真实定价（2026 年，俄勒冈区域）**：

*Personal 套餐（独占一台，AlwaysOn = 一直开机）*
| 套餐 | 配置 | 月费 |
|---|---|---|
| Value | 1 vCPU / 2GB | 约 $25 |
| Standard | 2 vCPU / 4GB | 约 $35 |
| Performance | 2 vCPU / 8GB | 约 $39 |
| Power | 4 vCPU / 16GB | 约 $60 |
| PowerPro | 8 vCPU / 32GB | 约 $88 |
| GraphicsPro | 8 vCPU / 32GB + GPU | 约 $220 |

*Personal AutoStop（不用就自动关机，按小时收费）*
- Windows Standard：约 **$44/月**（含一定小时数）
- Ubuntu Power：**$7.25/月 + $0.66/小时**

*⭐ 关键发现：VDI 合作伙伴捆绑包（这是给我们这种转售商准备的）*
- Windows Value Bundle：**$16.80 / 虚拟桌面 / 月**
- Power Bundle：**$5.80/月 + $0.51/小时**
- 这是 AWS 专门给**渠道商**的价格，比自己租便宜一半以上。

*⭐ 规模效应（1000 用户实测案例）*
- 多会话（多人共享一台大机器）：月付 **$4,398.66/月 = 每人 $4.40**
- 同样是 1000 人，按小时付：**$15,836.25/月 = 每人 $15.84**
- **月付比小时付省 72%**

**免费试水**：
- 新 AWS 账号送 **$200 credits**
- 免费层：2 台 Standard AutoStop（每月 40 小时）+ 5 台 Performance AutoStop Ubuntu（每月 100 小时），**免费用 3 个月**
- ⚠️ AWS 账号必须选 **Paid account plan**，免费 plan 看不到 WorkSpaces 控制台

**⚠️ 两个必须躲开的坑（2026 年最新）**：
1. **2026-07-30 起，WorkSpaces Pools 不再接受新客户** —— 别再往这个产品上做规划
2. **PCoIP 协议的 WorkSpaces Personal，2026-07-31 后不再接新客户，2027-10-31 彻底停服** —— 统一迁到 **Amazon DCV** 协议
   - 对我们的影响：新开的机器一律选 **DCV**，不要选 PCoIP

**「一键开通」怎么调**：
```
1. CreateWorkspaces       → 开一台机器（指定套餐 / 系统 / DCV）
2. 等待 State = AVAILABLE（约 15–20 分钟）
3. CreateWorkspaceBundle / RegisterWorkspaceDirectory → 平台层配置
4. 用 RegisterWorkspaceDirectory + AD 或 Simple AD 分配用户
5. 用户用「WorkSpaces 官方客户端」登录（Windows / Mac / iOS / Android / Web 全都有）
```
- 用户拿到的登录信息 = **注册码 + 用户名 + 密码**，这三样在任何设备上都能登录
- **完全不需要我们的 App** —— 这一步天然满足你「不用我们平台也能登录」的要求

**门槛**：
- 需要 AWS 账号（可注册，用中国身份证/护照都行）
- 需要先开通 WorkSpaces 服务（部分地区要提交申请，描述用途）
- 需要配一个目录服务（Simple AD 起步版约 $36/月，这是固定成本要注意）

### 1.2 阿里云无影（国内最快，但要求中国公司）

**为什么值得看**：无影是阿里云自研的云电脑，最大优势是**它有一套省级代理体系**。意思是——你不需要自己去阿里云官网开账号、走企业认证，你可以找**省级代理**拿货，代理会帮你搞定资质和贴牌。

**技术实力（官方指标）**：
- 自研 **ASP 2.0 协议**：会话建立 <1 秒，端到端延时 **20 毫秒**，支持 144fps、8K
- 流化带宽只需 **150Kbps**（网络差也能用）
- 40+ 项专利

**多端覆盖（关键）**：
- 软终端：Windows / Mac / 手机 / 平板 / **网页浏览器**
- 硬件终端：
  - **无影魔方**：功耗 **10W**（对比传统 PC 90W，年电费从 788 元降到 88 元）
  - 无影魔方 Pro、一体机 US01、笔记本 NS01

**硬件终端的意义**：这是给「真的没有电脑」的人用的 —— 插上显示器键盘就是一个工位，功耗 10W，成本远低于买一台 4000–8000 元的 PC。

**代理怎么找**：直接搜「无影云电脑 + 你所在省 + 代理」，例如杭州云无踪是无影浙江省省级代理。代理商能提供：
- 云电脑资源（基础办公型 / 图形工作站型）
- 硬件终端
- 全平台软终端

**⚠️ 门槛**：国内云桌面服务基本都要求**中国大陆企业营业执照**。你目前护照过期只有身份证，公司还没注册 —— **这条路的门槛在于公司资质，不是技术**。

### 1.3 自建（最便宜，但你要自己扛）

**做法**：在 Vultr / DigitalOcean / 阿里云 ECS 上开 Windows/Linux 虚拟机，自己装远程桌面，用户拿 RDP 账号密码连。

**成本**：$5–20/月/台（按配置）

**优点**：
- 完全白牌，客户看到的是我们的品牌
- 完全自主，没有服务商停服风险
- 凭据就是标准 RDP，任何远程桌面软件（Windows 自带、Microsoft Remote Desktop、AnyDesk 等）都能连

**缺点**：
- 没有「云电脑」那种秒级开关机和低延时流化体验，本质是「远程连一台服务器」
- 你要自己维护（系统更新、安全补丁、被攻击）
- **不推荐现在做** —— 除非你想练手，否则 AWS / 无影已经帮你解决了这些问题

**对比参考**：传统 PC 采购成本 4000–8000 元/台，且需要维护、电费、折旧；云电脑把这些全变成月租。

## 2. 「一键开通」的完整实现路径

### 2.1 整体架构

```
用户在我们 App 里点「开通云电脑」
        ↓
我们的后端收到请求（Node 服务）
        ↓
后端调用服务商 API（AWS WorkSpaces / 无影）
        ↓
机器创建完成（15–20 分钟，异步）
        ↓
服务商返回：注册码 / 用户名 / 初始密码
        ↓
我们把这三样存进数据库（加密），推送给用户
        ↓
用户在我们 App 里看到，同时收到邮件/短信
        ↓
用户可以直接点「打开」→ 跳转官方客户端 / 网页版登录
```

### 2.2 数据库要加的表（spec）

```sql
-- 云电脑实例表
CREATE TABLE cloud_desktops (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,              -- 归属用户
  provider TEXT NOT NULL,             -- 'aws-workspaces' | 'aliyun-wuying'
  provider_workspace_id TEXT,         -- 服务商侧 ID（异步回填）
  plan TEXT NOT NULL,                 -- 'standard' | 'power' | 'graphics'
  region TEXT NOT NULL,               -- 'us-west-2' 等
  protocol TEXT,                      -- 'DCV' | 'ASP2'
  state TEXT NOT NULL,                -- 'creating' | 'available' | 'stopped' | 'error' | 'terminated'
  created_at INTEGER NOT NULL,
  available_at INTEGER,
  terminated_at INTEGER,
  monthly_cost_cents INTEGER,         -- 我们支付的成本（分）
  billed_to_user_cents INTEGER,       -- 我们向用户收的（分）
  auto_stop_minutes INTEGER,          -- 空闲自动关机时间
  FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 凭据表（关键：加密存储，且必须能导出给用户）
CREATE TABLE cloud_desktop_credentials (
  desktop_id TEXT PRIMARY KEY,
  registration_code TEXT,             -- 注册码（AWS）
  username TEXT NOT NULL,
  password_ciphertext BLOB NOT NULL,  -- AES-256-GCM 加密
  password_iv BLOB NOT NULL,
  password_tag BLOB NOT NULL,
  realm TEXT,                         -- 域/租户
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (desktop_id) REFERENCES cloud_desktops(id)
);

-- 开通任务表（异步，因为要等 15-20 分钟）
CREATE TABLE desktop_provision_jobs (
  id TEXT PRIMARY KEY,
  desktop_id TEXT NOT NULL,
  request_payload_hash TEXT NOT NULL, -- 幂等
  status TEXT NOT NULL,               -- 'queued' | 'running' | 'succeeded' | 'failed'
  attempts INTEGER NOT NULL DEFAULT 0,
  last_error TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 2.3 「保留密码、不用我们平台也能登录」怎么落地

这是整个需求里**最容易做错**的地方，必须做对：

**正确做法（三条同时给）**：
1. **我们在 App 里显示完整凭据**（注册码 + 用户名 + 密码），用户能看能复制
2. **同时发一封邮件**（复用已有的 `account-mail.mjs` 邮件适配器），邮件里带官方客户端的下载链接
3. **在 App 里放「官方客户端下载」入口**，明确告诉用户：不用我们的 App，用官方客户端也能连

**必须做到**：
- 密码**不加密存储在我们的数据库里就当没这回事** —— 我们存的是加密版，但用户随时能点「查看密码」明文导出
- **绝不**做「密码只有我们能看到」这种设计 —— 那是锁定用户，违反核心承诺
- 服务商侧的开通，用**用户自己的邮箱**作为账号标识（而不是我们的统一账号），这样即使用户以后想自己续费也能接管

**⚠️ 一个容易踩的坑**：
AWS WorkSpaces 的密码是**通过目录服务（AD）管理**的，重置密码需要调 `ResetWorkspacePassword` API。要做「用户自己改密码」的功能，需要把这个 API 也接上，否则用户改不了密码只能找我们。**这个功能必须一开始就有。**

### 2.4 「一键开通」的业务流程（用户视角）

```
第 1 步：用户在 App 里选套餐
        □ 基础办公（¥XX/月）—— 2核4G，能办公能上网
        □ 图形/开发（¥XXX/月）—— 8核32G，能跑 AI、能开发

第 2 步：点击「开通」
        → 显示进度条（预计 15–20 分钟）
        → 后台异步创建

第 3 步：创建完成
        → 推送通知：「你的云电脑好了」
        → 显示：注册码 / 用户名 / 密码（可一键复制）
        → 提供：官方客户端下载链接（iOS / Android / Windows / Mac / 网页）

第 4 步：用户使用
        → 可以直接在我们 App 里嵌入网页版（体验最顺）
        → 也可以用官方客户端（体验最好）
        → 也可以完全不用我们，自己拿凭据去连
```

## 3. 成本与定价模型

### 3.1 成本结构（以 AWS 为例）

| 成本项 | 金额 | 说明 |
|---|---|---|
| 虚拟桌面（VDI 捆绑包） | $16.80/月 | Windows Value Bundle |
| 目录服务（Simple AD） | $36/月 | **固定成本，多人分摊** |
| 存储 | $0.08/GB-月 | 按硬盘大小 |
| **单用户月成本（10 人分摊）** | **约 $20.4** | 16.8 + 3.6 |
| **单用户月成本（100 人分摊）** | **约 $17.2** | 16.8 + 0.36 |

**⚠️ 巨大的隐藏成本**：目录服务 $36/月是固定的，1 个人用也是 $36，100 个人用也是 $36。所以**必须凑够用户量才划算**。

### 3.2 规模效应的真相

- 10 个用户：单用户成本约 $20
- 100 个用户：单用户成本约 $17
- 1000 个用户（多会话模式）：**单用户成本 $4.40**

**这意味着**：起步阶段做云电脑是**亏的**（固定成本摊不开）。**必须等到有一定用户量才上线这个功能。**

### 3.3 建议定价

| 套餐 | 我们的成本 | 建议售价 | 毛利 |
|---|---|---|---|
| 基础办公 | ~$20 | **¥199/月** | 约 30% |
| 图形/开发 | ~$40 | **¥399/月** | 约 30% |

**为什么毛利只有 30%**：这是重资产生意，不是软件生意。软件边际成本是 0，云电脑是每多一个用户就多一份成本。**这一点你必须清楚，它和钱包、积分完全不同。**

## 4. 三个必须做对的事（合规 & 风险）

### 4.1 ⚠️ 不要变成「二房东」

如果我们直接向用户收钱、机器在我们账号下、用户只是「租用」—— 这在部分司法辖区可能被视为**转售电信/云服务**，需要相应资质。

**规避方法**：
- 优先走有**明确渠道/代理商体系**的服务商（AWS VDI 合作伙伴、无影省级代理）—— 这类渠道本身就是为转售设计的，合规链条清晰
- 和代理签正式的分销协议，别自己去官网开账号硬转售

### 4.2 ⚠️ 用户数据在我们租的机器上

云电脑上会有用户的文件、账号、密码。虽然我们技术上不主动看，但**我们持有这台机器的管理权限**。

**必须做到**：
- 用户协议里明确写清：机器上数据的归属、我们的访问边界
- 在 App 里提供「一键销毁」功能（用户随时能彻底删掉这台机器和数据）
- 绝不用管理权限去翻用户的东西 —— 这是信誉底线

### 4.3 ⚠️ 这个方向和钱包的合规问题不是一回事

- **钱包**：涉及 FinCEN money transmission，我们选择「不碰用户的钱」来规避
- **云电脑**：不涉及资金，但涉及**数据处理者责任**和可能的**电信转售资质**

**两件事要分开处理，不要混在一起想。**

## 5. 落地顺序（我的建议）

### 第 1 步：不要写代码，先手动验证（本周就能做）

**做法**：你自己去 AWS 开一个账号，手动开 **3 台**云电脑，送给 3 个你认为「真的没有电脑」的人用一个月。

**要观察**：
1. 他们**真的会用吗**？（还是开了一天就忘了）
2. 他们**会第二次登录吗**？
3. 他们遇到问题，**会不会来找你**？

**为什么必须这么做**：
> 「大部分人都是没电脑，没有时间去弄」

这句话是你的**核心商业假设**。它如果错了，整个云电脑方向就白做了。而验证它只需要 $200（AWS 送的 credits 就够了），不需要写一行代码。

**这是整份文档里最重要的一条建议。**

### 第 2 步：如果验证通过，接 AWS WorkSpaces API

- 用免费层 + $200 credits 把「一键开通」的代码跑通
- 先做**内部**（你自己 + 几个朋友），不对外开放
- 把数据库三张表加上（第 2.2 节）

### 第 3 步：等用户量起来，再谈代理价

- 用户数 < 50：直接用 AWS，成本可接受
- 用户数 > 100：开始谈 VDI 合作伙伴价 或 无影省级代理
